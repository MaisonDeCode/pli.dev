**Pli.Sheets** is a spreadsheet engine and grid editor with formulas, charts and formatting. It is number 2 on the [main roadmap](/roadmap/). The engine and a React grid editor are built, tested and documented. See [Sheets](/sheets/) for how it is offered.

## Still to build

- [ ] Look at the check kit files in Excel by eye (21 to 42), beyond opening them: all of 22 to 42 now open in Excel for Mac and were saved back (11 Nov 2026). That pass found three things Excel repaired or removed, all fixed: an empty `<pages>` in a pivot cache with no page fields (it dropped both consolidation pivot tables of file 36), a function named on its own as an argument, which Excel writes `_xleta.SUM` (without it every `GROUPBY` cell was `#NAME?`), and optional `LAMBDA` parameters, which Excel declares `_xlop.y` (it removed all four formulas of file 42's Lambda sheet). Formula counts agree in every file. Looked at in Excel's own window: the charts of file 31 (all 21 draw; the histogram bins read ≤ 2: 3, (2,5]: 6, (5,8]: 2, (8,11]: 3, (11,14]: 4, > 14: 2, as written). Not looked at by eye yet: files 22 to 30 and 32 to 42 beyond opening and saving them. Excel for Mac does not keep a table's `sortState` whatever is written (files 06 and 35; it is Excel's behaviour, noted in [Tables](/sheets/tables/#in-xlsx-files)), and file 36's "Kept" pivot and file 25's "PickedGroup" and "Hours" came back from Excel in forms Pli read as plain cells, now read as pivot tables. Each file's `see` list says what to compare.
- [ ] Check what we write against Excel itself, the rest: files 01–20 of the check kit open in real Excel (Mac) with no repair message, Excel saved all of them back and `pnpm excel-check:read` finds nothing to look at (172 of 172 formulas agree). Also looked at in Excel itself: the passwords `pli` and `wb` (a wrong one doesn't unprotect), iteration, links, notes (the red corners), slicers, sparklines (all three kinds), every pivot table of files 15, 17 and 20, the eight charts, the table sample, and printing (the Report sheet is 5 pages, the Wide sheet 2). Files 01–18, 20 and 21 were compared with Excel's re-saved copies part by part and by reading both back (11 Nov 2026): Excel only rewrote formats' escapes, re-salted the password hashes, and dropped what it treats as default, and the two things Pli had to learn are fixed (Excel flattens the Hyperlink style to plain colours, and writes its default width on columns that only carry an outline). Still to do by hand: save kit file 19 from Excel into `excel-check/back/` (there is no Excel copy of it), open Pli's Google Sheets copies, and the Chrome, Safari and Firefox clipboards. Excel also drops a table's sort levels (files 06, 32 and 35) and a data bar written without the 2010 extension is saved back as `axisPosition="none"`. The files are made by `pnpm excel-check:make` ([how](/sheets/files/#checking-against-excel))
- [ ] Charts, look in Excel: kit file 60 (`excel-check/60-charts-detail.xlsx`) asks four things only Excel's window can answer, because Excel writes none of them into the file: how long its standard deviation and standard error bars are (Pli draws STDEV.P and STDEV.S/√n), what R squared it gives a trendline forced through (0, 2) (Pli: 0.9521), whether it shows both series of a histogram (file 31 comes back with the second marked `hidden`), and whether a Combo chart may have a bar series with a column or line. It also checks that Excel keeps the point colours, axis fonts and titles in pieces, trendline labels, scatter points on columns, stacked lines, 3-D perspective, spheres and treemap and sunburst labels Pli now writes. [What is missing](/sheets/charts/#not-there-yet)
- [ ] `FORECAST.ETS`: Excel's numbers are close to Pli's but not equal (kit file 42: with the same series Excel gives a forecast of 21.046 for step 21 where Pli gives 21.137, alpha 0.126 where Pli finds 0.1, RMSE 0.747 where Pli has 0.693); Excel's starting states and search are not published and its squared errors are not the smallest, so matching it to the digit needs more of Excel's answers on small, simple series (extra cells for the Forecast sheet of file 42). Everything else in kit file 42 now matches Excel (`GROUPBY`, `PIVOTBY`, the complex numbers). `LAMBDA(x,x+1)(5)` is built and waits for Excel's answer for the two new Lambda cells

To teach the reader what Excel really writes, give a picture an artistic effect in Excel, save it and send the file (the `xl/media/hdphoto1.wdp` inside shows how Excel codes the original; Pli's reader has been checked against the reference implementation's files, which is not the same as Excel's own). - [ ] Links and notes, the rest: look at kit files 26 and 38 in Excel (picture fill, opacity, dashed lines; Excel's copy writes a note's shadow switched off by leaving `on` out, which Pli now writes and reads the same way)
- [ ] Protection, the rest: look at kit files 28 and 39 in Excel (delete rules, table refusal, `FORMULATEXT` of a hidden formula, account permissions)
- [ ] Printing, the rest: look at kit files 29 and 40 in Excel (header picture shape ids: Excel's copy keeps them as written; overflow, draft, shown-note clipping), and the PDF's charts and icons in a real browser's PDF viewer
- [ ] Groups, subtotals and sparklines, the rest: look at kit files 13, 30 and 41 in Excel (Excel's copy of 41 draws the pivot table with its own style, so the bold and fill Pli puts on its cells are not kept there)
- [ ] Fonts, in Excel: open an XLSX that names a Google font (`Lora`, `Roboto Mono`) in Excel on a computer without it, and see which font Excel picks from the `<family>` hint (also a file written with `{ fonts: "office" }`). See [Fonts](/platform/fonts/#fonts-in-files)
- [ ] Threaded comments, in Excel: open a file written by `toXlsx` with threads (replies, a resolved thread, a mention) in Excel 365 and in Google Sheets, check that the thread, its replies, the resolved state and the people show, that the classic `[Threaded comment]` placeholder note stays hidden behind them, and send the XML Excel saves (the parts follow Excel's documented shape and are checked by reading them back, but no copy of Excel has opened them)
- [ ] Live editing, over a real network: the merge rules are tested through real clients and a stepped network (delays, offline, undo); put two browsers on a Socket.io server with `createAuthority` (the playground's `collab-server.ts` registers the `sheet` kind) for a few minutes of typing, row insertion, table, slicer and pivot edits and sheet reordering, which only real timing shows
