`@pli.dev/sheets-react` is a spreadsheet for React 18 and 19: a title and menu bar, a virtualized grid, formula bar, toolbar, sheet tabs and a status bar, driven by a [`SheetSession`](/sheets/getting-started/). Install it with `npm install @pli.dev/sheets @pli.dev/sheets-react` (it needs `react` and `react-dom` in your app). The playground has it running: from a clone of the repository, `pnpm playground`, then open Sheets.

```tsx
import { PliSheet, useSheetSession } from "@pli.dev/sheets-react";
import "@pli.dev/sheets-react/styles.css";

export function Budget() {
  const session = useSheetSession();    // a new workbook; or useSheetSession(parseWorkbook(saved))
  return (
    <div style={{ height: "100vh" }}>    {/* it fills its container: give it a height */}
      <PliSheet session={session} />
    </div>
  );
}
```

The workbook lives in the session. Save it with `serializeWorkbook(session.state)` (see [Files and formats](/sheets/files/)), and replace it with `session.load(workbook)`. `useSheetRevision(session)` re-renders your own components when it changes.

## The title and the menus

The title at the top-left is the workbook's name (`session.state.title`). Click it to rename the spreadsheet. It is used for the names of downloaded files. Typing a name isn't an undo step, so Undo takes back your last edit to the cells. Sheets are renamed on their tabs: double-click a tab, or use the arrow on the active tab, which renames, colours (**Tab color**), moves, hides and deletes the sheet. Ctrl or Cmd+click adds tabs to the ones picked and Shift+click picks a run of them, and the menu then hides or deletes them all at once. Right-clicking a tab opens the same menu, plus **New sheet**. Right-clicking the empty space in the sheet bar offers **New sheet** and **Unhide**, which lists the hidden sheets. At least one sheet always stays shown. A sheet's `hidden` and `tabColor` are kept in the workbook and in XLSX files.

The menu bar is the same one Pli.Documents has:

| Menu | |
|---|---|
| **File** | Download as Excel (.xlsx), the current sheet as CSV or tab-separated, or Pli JSON; Import an XLSX, CSV, TSV or JSON file (asks before replacing a spreadsheet that has data, and lists what couldn't be carried over) |
| **Edit** | Undo, Redo, Cut, Copy, Paste, Select all, Clear contents and formatting, Delete row and column |
| **View** | Freeze rows and columns; show or hide the toolbar, formula bar and status bar |
| **Insert** | Rows above and below, columns left and right, a function (starts a formula such as `=SUM()` with the cursor inside), a [chart](/sheets/charts/) of the selected cells, checkboxes, dropdowns and badges, and a new sheet |
| **Format** | Number formats and decimals, bold, italic, underline, strikethrough, alignment, wrapping, clear formatting |
| **Data** | Sort A to Z and Z to A, [Custom sort](/sheets/tables/#sorting-by-several-columns-by-colour-and-by-icon) (several levels, by colour or icon), [Remove duplicates](/sheets/tables/#removing-duplicate-rows), create or remove a filter, filter views |

## Help while typing a formula

Typing `=` opens a list of the common functions, and each letter narrows it to the functions (and your [defined names](/sheets/getting-started/)) that match. The highlighted one has a card beside it: its syntax, what it does, each argument, and an example with what it gives.

- Up and Down move through the list, Enter or Tab put the function in with its bracket, and Escape closes the list (a second Escape cancels the entry). Clicking a function picks it too.
- Once you are inside a function's brackets, a hint shows its syntax with **the argument you are on in bold**, and what that argument is. It follows the caret as you type commas, ignores commas in text and in `{1,2,3}` arrays, and shows the function you are in when brackets are nested.
- The same help shows when you type in the formula bar.
- The entry carries on when you switch sheets. Type `=SUM(`, click another sheet's tab, and click or drag cells there: they go into the formula with the sheet's name (`=SUM('Sales 2025'!B2:B9`). Enter or Tab finishes the formula on the sheet you started on, adding any closing brackets you left off, and takes you back to it; Escape cancels. Plain text (no `=`) is entered when you switch.
- A formula that fills several cells (`=SORT(...)`, `=FILTER(...)`) shows its results in the cells below it, and selecting the formula's cell outlines the whole range. See [Arrays that spill](/sheets/formulas/#arrays-that-spill).
- The list and the cards come from a catalog in `@pli.dev/sheets` (`functionCatalog()`, `functionInfo("SUM")`, and `assistFormula(text, caret)` for the logic), so another front end can show the same help. A test checks that every function has an entry, that its arguments match what the function accepts, and that its example works.

## Checkboxes, dropdowns and badges

**Insert > Checkbox, Dropdown… and Badge** turn the selected cells into controls, and **Insert > Remove checkbox, dropdown or badge** takes it off again. A control is a property of the cell (`cell.control`), so it is saved with the workbook, copies and fills with the cell, and the cell's value is still an ordinary value that formulas read.

| | Value | How people use it |
|---|---|---|
| **Checkbox** | `TRUE` or `FALSE` (or any two values you choose, such as "Yes" and "No") | Click the box, or press Space (it ticks every selected checkbox together). Delete unticks. Typing in one is refused, and so is any other value |
| **Dropdown** | The text of a choice | Select the cell and click the arrow (or press Alt+Down, F2, or double click) to open the list. Each choice has a colour and shows as a badge. Options: allow several choices (kept as text joined with `, ` or a separator you choose, see [A separator for dropdown cells](/sheets/validation/#a-separator-for-dropdown-cells)), and refuse anything that isn't a choice. Edit one from the right-click menu |
| **Badge** | Text | A pill showing the cell's text, in a colour you choose. With a **kind** it shows what the value means to your app (below) |

Insert > Dropdown… opens a small dialog for the choices and their colours.

### Badges for your own data, such as people

A badge of a **kind** keeps an id in the cell and asks your app what it stands for, so a cell can show a person's name and picture while a formula (and the saved file) sees the id. Describe the kinds in the `chips` prop:

```tsx
import { PliSheet, type ChipKind } from "@pli.dev/sheets-react";

const chips: Record<string, ChipKind> = {
  person: {
    label: "Person",                                   // the name in Insert > Badge
    resolve: (id) => {                                 // what to show for an id
      const p = directory.get(id);
      return p && { value: p.id, label: p.name, image: p.photoUrl, color: "#e0e7ff", description: p.role };
    },
    search: async (query) =>                           // what the picker lists as people type
      (await directory.find(query)).map((p) => ({ value: p.id, label: p.name, image: p.photoUrl, description: p.role })),
    // render: (item) => <MyChip item={item} />,       // optional: draw the badge yourself
  },
};

<PliSheet session={session} chips={chips} />
```

Insert > Badge > Person makes the selected cells person badges and opens the picker, a search box over what `search` returns, with each person's picture, name and detail. Choosing one puts their id in the cell. With `multiple` on the cell (`{ type: "badge", kind: "person", multiple: true }`) people are added and removed one at a time. A value `resolve` doesn't know shows as plain text. `ChipOption` is `{ value, label?, color?, description?, image? }`.

#### A card of your own when a badge is clicked

Add `card` to a kind and clicking one of its badges opens whatever you draw, under the badge, such as a profile with buttons:

```tsx
person: {
  label: "Person",
  resolve, search,
  card: (person, { close }) => (
    <div>
      <img src={person.image} alt="" width={48} />
      <strong>{person.label}</strong>
      <p>{person.description}</p>
      <button onClick={() => { openProfile(person.value); close(); }}>Open profile</button>
    </div>
  ),
},
```

- Mouse and touch. A plain click (or tap) on the badge selects the cell as usual and opens the card when the pointer is let go; in a cell with several badges, the one clicked. Clicking the same badge again closes it. A drag that starts on a badge still selects a range. Ctrl, Cmd, Shift and Alt clicks do not open it, so Ctrl or Cmd+click on a cell with a link still follows the link, and Shift+click still extends the selection. The dropdown button, double click, F2 and Alt+Down still open the picker (which closes the card).
- Keyboard. With the cell selected, **Space** or **Alt+Enter** opens the card (of the first badge, if the cell holds several), and the cell announces "press Space for details". Plain Enter keeps moving down, as in every cell. Focus goes into the card (its first button or link, else the card itself); **Escape** closes it and puts focus back on the grid, and so does a click anywhere else, resizing the window, or moving the selection off the cell.
- A value your `resolve` doesn't know has no card. The card is shown on read-only sheets too (it is yours to decide what its buttons do). It is drawn inside the spreadsheet as a `role="dialog"` named by the badge's label, with the class `pli-chipcard`.

From code, `session.setControl(sheet, "B2:B9", { type: "checkbox" })`, `session.toggleCheckbox(sheet, "B2")`, and `session.pickChoice(sheet, "D2", "u_ann")` do the same things; the [Get started](/sheets/getting-started/) page lists them.

## Find and replace

The bar is part of `PliSheet`. The same search is on the session, for your own interface:

```ts
const options = { text: "smith", matchCase: false, scope: { sheet: "Sheet1" } };
session.find(options);                          // [{ sheet, address: "A2", text: "Ana Smith" }, …]
session.replace(options, "Wright");             // { cells: 2, occurrences: 2, skipped: 0 }, one undo step
session.replace(options, "Wright", [first]);    // only the cells you give it
```

- What it looks at. `lookIn: "values"` (the default) is what the cells show: `12%`, `$1,956.00`, and the values a formula spilled. `"formulas"` is what was typed: `=C2*2`, or `0.12` for the percentage. `"notes"` is the text of the cells' notes (Excel's Look in: Notes): a hit is a cell whose note has the text, with `in: "note"` and the note's text, and the cells themselves are not looked at. In the bar, **Look in** has the three, and the cells whose notes match are marked and stepped through like any others (the selected cell shows its note on its card).
- Where. `scope` is `"workbook"` (every sheet that isn't hidden, or every sheet with `hidden: true`), or `{ sheet }` for one sheet (hidden or not), with a `range` to look in part of it. Results come sheet by sheet, by rows or by columns (`by`).
- Errors. `errors: true` finds only cells that hold an error, whatever the cell shows: with empty `text` every one of them, with text the ones whose error matches (`"#DIV"`).
- A look. `format: { bold: true, fill: "#ffff00", … }` finds only cells with that look: `bold`, `italic`, `underline`, `strike` (`false` means the cell doesn't have it), `fill` (`"none"` for no fill), `color` (`"auto"` for the default), `fontFamily`, `fontSize`, `align` and `fmt` (the number format code). Every property given must match. With empty `text` every cell with the look is found, empty ones too; with text, the cells that have both. Errors and a look can be asked together. Replacing needs text to replace.
- How. Matching ignores capitals unless `matchCase` is set, finds the text anywhere in a cell unless `wholeCell` is set, and reads `*`, `?` and `~` as Excel does. With `regex` the text is a JavaScript regular expression, and a replacement can use `$1`, `$<name>` and `$&`. A pattern that doesn't parse throws.
- **Replacing** works on what was typed, formulas included, whatever `lookIn` says (Excel does the same), and the result is typed in again: `1` to `2` in `10` makes the number `20`, a formula that no longer parses shows an error, and a cell of text such as `007` stays text. Formatting stays. Replacing with nothing clears a cell.
- **Notes** (`lookIn: "notes"`): replacing changes the note's text, in all of the notes or the ones you give it, as one undo step. A note with a look keeps it: text swapped inside one run keeps that run's look (when the text spans runs, it takes the look of the run where it began), and the rest of the note keeps its own. A note, its author and its box are otherwise as they were; a note left with no text is taken off, as an empty note is none. Changing notes needs the right to edit objects on a protected sheet.
- **What it leaves alone**, counted in `skipped`: a checkbox or strict dropdown that wouldn't take the new text, and a table's column name that would become empty or a copy of another one, and a note that would be longer than 32,767 characters. Renaming a table's column this way renames it in formulas as typing over it does.
- **In a table's calculated column**, replacing in every cell of the column gives the column the new formula; replacing in only some leaves the column as it was and marks those cells as not following it; replacing in one cell changes the whole column, as typing a formula into it does.

## Filters by condition

A filtered column lets through a list of values, or what a rule says. In the filter menu choose **Filter by condition…**. In code, `filterColumnRule` (the sheet's filter) and `filterTableRule` (a table's) take a rule, and `null` lets everything through again. Setting a list of values on the column takes the rule off, and the other way round.

```ts
session.filterColumnRule("Sheet1", 2, { kind: "custom", a: { op: "greaterThanOrEqual", value: 10 }, b: { op: "lessThan", value: 40 } });   // between: joined by and
session.filterColumnRule("Sheet1", 1, { kind: "custom", a: { op: "contains", value: "pie" } });
session.filterTableRule("Orders", "Amount", { kind: "top", n: 10, percent: true });
session.filterTableRule("Orders", "Day", { kind: "date", period: "thisMonth" });
session.filterColors("Sheet1", 3);   // { fills: ["none", "#ffff00"], fonts: ["auto", "#0000ff"] }: what a colour filter can pick
```

- **Comparisons** (`kind: "custom"`): one, or two joined by and (the default) or `or: true`. Operators: `equals`, `notEquals`, `greaterThan`, `greaterThanOrEqual`, `lessThan`, `lessThanOrEqual`, `contains`, `notContains`, `beginsWith`, `notBeginsWith`, `endsWith`, `notEndsWith`, `blank` and `notBlank`. Text ignores capitals. `equals` and `notEquals` understand `?` (any one character) and `*` (any text), and `~` takes the meaning away from the next one, as in Excel. A number compares as a number, text typed as a date (`2025-03-15`) as a date, and text as text; an empty cell passes only `blank`, `notEquals` and `notContains`.
- **Top and bottom** (`kind: "top"`): the `n` greatest numbers, or with `bottom: true` the least, or with `percent: true` the greatest (or least) `n` percent of the numbers, at least one. Equal numbers at the edge all pass.
- **Average** (`kind: "average"`): the numbers above the average of the column, or with `below: true` below it.
- **Dates** (`kind: "date"`): `today`, `yesterday`, `tomorrow`, `thisWeek`, `lastWeek`, `nextWeek` (weeks start on Sunday), the same for `Month`, `Quarter` and `Year`, `yearToDate`, and a quarter (`q1`…`q4`) or month (`m1`…`m12`) of any year. They count from today, so a filter on `thisMonth` hides different rows next month once it is reapplied.
- **Colour** (`kind: "color"`): cells with a fill (`fill: "#ffff00"`, or `"none"` for no fill) or a font colour (`font: "#0000ff"`, or `"auto"`). The colours are those the cells' own style gives them; a colour from a table's style or a conditional format isn't counted.

A rule is kept in the filter (`filter.columns` for the sheet's, `table.filters` for a table) next to the lists of values, so it follows its column when columns are inserted, deleted or renamed, saves with the workbook, and is one undo step. The filter is not applied again when cells change until `reapplyFilter` (or `reapplyTableFilter`), as in Excel, so a top 10 or an average is worked out when the filter is applied. A slicer on a column that has a rule shows every value as chosen until a button is pressed; slicers still see the rules on other columns.

In XLSX files a comparison is a `customFilters` element (a pattern such as `*pie*` for contains), a top or bottom is `top10`, an average or a period of dates is a `dynamicFilter`, and a colour is a `colorFilter` that points at a style. LibreOffice reads and writes comparisons, tops and colours; it has no averages or periods, and drops them (Pli keeps the hidden rows). A filter that picks dates by year, month and day (Excel's date tree) is `dateGroupItem` elements inside `filters` and is read and written (see [Tables](/sheets/tables/#dates-picked-from-the-tree)); one that Pli can't read (another calendar, say) is left out with a warning and its rows stay hidden.

## Filter views

A filter view is the sheet's filter saved under a name, so people can switch between ways of looking at the same data (this quarter, only mine, the biggest first). It holds the filter's range, what each column lets through (lists of values and rules), optionally a column to sort by, and what each table on the sheet filters and is sorted by.

In the grid, **Data > Filter views** lists the views of the sheet with a tick on the one showing, **Save current filter as a view…** and **Manage views…**. The dialog saves the filter in force, and the filters and sorts of the sheet's tables, under a name (optionally with a column of the sheet's filter to sort by; a sheet with only a filtered table can be saved too), says in a few words what each view holds, and for each view has **Show**, **Apply for everyone**, **Update** (replace what the view holds with the sheet's filter as it is now), a name you can edit, and **Delete**.

- Showing a view changes nothing for anyone else. The rows a view hides are hidden only in your grid (a bar over the grid says which view is showing, with **Close view** and **Apply for everyone**); the workbook, other people's grids and undo history are untouched. Which view you are showing is not saved. The view follows edits to the data, and a view whose rows are all let through by the sheet's own filter shows more rows than the sheet does.
- **Apply for everyone** makes the view the sheet's own filter (one undo step): the sheet's filter is replaced, rows are hidden and shown to match, and a view with a sort sorts the data first (sorting moves cells, so that is for everyone, and is refused if merged cells are in the way). Looking at a view needs no permission; saving, changing and deleting them needs a protected sheet to allow filters, and applying one that has a different range from the sheet's filter is refused on a protected sheet, as making a filter is.
- The rows you hid by hand stay hidden.
- A view's sort is shown, not applied. While a view with a sort shows, the grid draws a copy of the workbook with the view applied (`session.previewFilterView(sheet, view)` makes it, or gives `null` when the view sorts nothing or the sort can't be done): the rows come in the view's order, the formula bar and the status bar's totals read the copy, nothing in the sheet moves, and editing is off until you close the view or apply it.
- Tables. A view keeps, for each [table](/sheets/tables/#filtering-and-sorting-from-the-header) with a header row, the filters on its columns (by column name) and the column it was sorted by. A view that holds tables says it all: while it shows, a table is filtered as the view says, so a table the view has no filter for shows every row, whatever its own filters are. The table itself is not touched (its filters, its sort mark and its cells stay as they are, for everyone else). A view saved on a sheet with no tables, or an old one, has no word about tables, and the tables keep their own filters while it shows. Applying a view for everyone sets the filters of each table to the view's, sorts the table by the view's sort (the cells move; a table the view doesn't sort keeps the order it has), and hides the rows to match, in the same one undo step; if any sort can't be done (merged cells, a sort that overlaps another) nothing is changed.

```ts
const view = session.saveFilterView("Sheet1", "Reds", { sort: { column: 3, descending: true } }); // the sheet's filter, by name; undoable
session.filterViews("Sheet1");                         // [{ id, name, range, columns?, sort? }, ...]
session.renameFilterView("Sheet1", view.id, "Red team");   // a view is found by id or by name
session.updateFilterView("Sheet1", "Red team");        // hold the sheet's filter and tables as they are now ({ sort } changes or, with null, drops the sort)
session.canSaveFilterView("Sheet1");                   // is there a filter, or a table with a filter or sort, to save?
session.filterViewRows("Sheet1", "Red team");          // { hide: [5], show: [3] }: what a grid draws for the view; changes nothing
session.previewFilterView("Sheet1", "Red team");      // a separate session with the view applied (sorted), to draw; null when the view sorts nothing
session.applyFilterView("Sheet1", "Red team");         // make it the sheet's filter, hide the rows, sort if it says so: one undo step
session.deleteFilterView("Sheet1", "Red team");
```

Names are unique on a sheet without regard to capitals (at most 80 characters), there are at most 100 views a sheet, and a view's range (left out when it holds only table filters) has at least two rows. A view's `tables` is `{ [tableId]: { filters?: { [column name]: criterion }, sort?: { column, descending? } } }`. Views live in `sheet.filterViews`, are checked when a saved workbook is read, follow their range and columns when rows and columns are inserted or deleted (a view whose range is deleted goes, and criteria and sorts on deleted columns are forgotten, in the sheet's filter and in its tables), and every change to the list is one undo step (`set_filter_views`).

**In XLSX files**, filter views are Excel's **named sheet views** (View > Sheet View in Excel for the web and Microsoft 365). Excel keeps them in a part of their own, `xl/namedSheetViews/namedSheetViewN.xml` (namespace `http://schemas.microsoft.com/office/spreadsheetml/2019/namedsheetviews`, content type `application/vnd.ms-excel.namedsheetviews+xml`), reached by an implicit relationship of type `http://schemas.microsoft.com/office/2019/04/relationships/namedSheetView` from the sheet. Each `namedSheetView` has a name and an `nsvFilter` for the sheet's AutoFilter (`tableId="0"`) and one for each table (`tableId` is the table's id), with the filters of its columns (`columnFilter`: the same `filters`, `customFilters`, `top10`, `dynamicFilter`, `colorFilter` Excel writes for an AutoFilter, with a `dxf` for a colour) and its sort (`sortRules`). The AutoFilters they belong to carry an `xr:uid` that the `nsvFilter` names in `filterId`, as Excel writes it. The workbook still holds the filter in force as an ordinary autofilter and table filters, with its rows hidden, so a program that doesn't know sheet views sees the sheet as it was saved (LibreOffice opens such a file with its filters, tables and values intact).

- Writing needs nothing from you: every view is written. A view that holds only table filters has no `nsvFilter` for the sheet; one that holds nothing at all is an empty `namedSheetView` (it shows everything).
- Reading brings back the names, the sheet's and the tables' column filters and a sort. An `nsvFilter` finds its table by `tableId` and its sheet's AutoFilter by `tableId` 0 (the `filterId` and `xr:uid` pairing, which Excel tries first, would give the same answer in a file Excel wrote with one AutoFilter and its tables). A view that names AutoFilters says the others are not filtered in it. What Pli can't keep is left out with a warning: filters of a kind Pli doesn't have (icon filters, other calendars), a sort by colour, icon or custom list, sorts by several columns (the first is kept), and views for tables or AutoFilters that are not in the file. Names are cut to 80 characters and made unique, and at most 100 views a sheet are read.
- Because a sheet view's columns are counted from the left of the sheet's AutoFilter, a view saved with a different range from the sheet's present filter is written for that filter's range and reads back with it. A view saved on a sheet that has no filter now (the filter was taken off) is written with its own range and no `xr:uid` to match, which Excel is allowed to drop and Pli reads back as it was.
- Google Sheets' own filter views are a different thing, in a format Pli doesn't read or write. Excel for Mac opened kit file 32 with no repair message and kept all three views, filters and sorts. It writes a sort's `ref` over the whole filter range with its header row (`C1:C9`); Pli writes it that way too and reads either form.

## Pointing with the arrow keys

While a formula is being typed, the arrow keys move the reference instead of the text cursor, as Point mode does in Excel. It starts when the formula expects a reference: after `=`, an operator, `(` or `,` (the same places clicking a cell works), and the reference is first the neighbour of the cell being edited.

- An arrow key puts the neighbouring cell in (`=` then Right in E2 gives `=F2`), and each following arrow key moves it on. The reference is drawn in colour and outlined on the sheet, like one that was clicked.
- Shift+arrow stretches it to a range from where it began (`=SUM(C1:C3`); an arrow key without Shift makes it one cell again, from the end of the range that was moved.
- Ctrl or Cmd+arrow jumps to the edge of a block of data, as it does outside a formula, and with Shift extends to it.
- Typing anything else keeps the reference where it is. An operator or `,` makes the next arrow key start a new reference. Moving the text cursor with the mouse, or typing, ends pointing. Clicking a cell while pointing replaces the reference.
- F2 switches to Edit mode, where the arrow keys move the text cursor (the formula text stays); F2 again returns to pointing. Entries that started by double click or F2 are in Edit mode, and so are entries in the formula bar (see below). Enter, Tab and Escape finish or cancel as usual.
- After the formula's text is complete (a number, a name, a closing bracket), an arrow key finishes the entry and moves. After a lone `=`, the up and down keys point at cells; once a letter is typed they pick from the list of functions again.
- With the entry carried onto another sheet (click its tab), the arrow keys start from the active cell there and name the sheet (`=Other!B1`).
- Dragging the outline. The coloured outline of a reference in the formula being typed can be dragged. Its edge moves the reference by as many cells as the pointer goes (the shape stays, the sheet's name in front of it stays, `$` signs stay where they were), and its bottom right corner stretches it, down to a single cell again. The text of the formula changes as you drag, and nothing is saved until the entry is finished (Escape cancels it). Only references to the sheet shown can be dragged, and a click anywhere but on an outline still puts a cell address in. Mouse, pen and touch all work.
- In the formula bar, entries start in Edit mode as in Excel, where the arrow keys move the text cursor. Press F2 to turn on Point mode, and the arrow keys then put in and move a reference exactly as above (Shift stretches it, Ctrl or Cmd jumps to the edge of the data, the sheet scrolls to the cell, the reference is outlined on the sheet, and with the entry carried onto another sheet it names the sheet). F2 again goes back to Edit mode, clicking in the bar's text does too, and typing keeps whichever mode it was in (an operator or `,` makes the next arrow key start a new reference). Where a reference couldn't go (after a number, a name or a closing bracket), or in Edit mode, the arrow keys are the text cursor's. `pointStep` in `packages/sheets-react/src/pointing.ts` is the one function both editors use.

## Groups

Rows or columns can be grouped, as in Excel's outline, so that detail can be folded away under its subtotal. Each row or column has a `level` (1 to 7); neighbours at one level or deeper make a group at that level, and the row below it (the column to its right) is its summary, which carries the `collapsed` mark and the button.

```ts
session.groupRows("Sales", 2, 3);            // rows 2 and 3 become a group, summed up by row 4
session.groupRows("Sales", 2, 7);            // another level around them
session.toggleGroup("Sales", "row", 4);      // collapse (or open) the group row 4 sums up: rows 2 and 3 are hidden
session.showLevel("Sales", "row", 1);        // only the top level shows; one more than outlineDepth shows everything
session.ungroupRows("Sales", 2, 3);          // takes a level off, and shows the rows if they were folded
session.outlineGroups("Sales", "row");       // [{ level, from, to, summary, collapsed }, …]
session.setOutlineSummary("Sales", { above: true, left: true });   // summaries above and left of the detail
```

- Collapsing: the rows or columns of a collapsed group are hidden (`hidden`, as any hidden row is) and the summary is marked `collapsed`. Opening an outer group leaves an inner group that was collapsed folded. Moving, inserting and deleting rows and columns takes levels and marks along.
- Limits: one change groups or ungroups up to 10,000 rows or columns. A group with no row or column to hold its button (the first row when summaries are above) can be made but not folded. Filters hide rows in the same way, so opening a group shows its rows even if a filter had hidden them (applying the filter again hides them).
- Protected sheets refuse grouping unless they allow formatting rows (for rows) or columns.
- Keyboard: Alt+Shift+Right groups the selected rows (or the selected columns, when whole columns are selected) and Alt+Shift+Left takes them out of the group, as in Excel.
- The outline margin: when a sheet has groups, a margin appears left of the row headings and above the column headings (and goes when the groups do). Each group has a bracket at its level, and the plus or minus sits on the summary row or column, one level in. In the corner are buttons numbered 1, 2, 3 and so on, one more than the groups are deep: the ones along the bottom show the rows down to that level, the ones down the left do the same for columns, and the last shows everything (`session.showLevel`). Data > Group > Show does the same from the menu.

## Subtotals

Excel's **Data > Subtotal**: in a list sorted by one column, a row of `SUBTOTAL` formulas goes under (or over) every run of equal values in it, for the columns you pick, with a grand total, and each run becomes a group that folds away under its subtotal (see [Groups](#groups)). The rows are ordinary rows with ordinary formulas, so nothing is lost in a file.

```ts
// A list with headings in row 1, sorted by Region: a Total row under each region, and a Grand Total.
session.subtotal("Sales", "A1:D20", { by: "Region", fn: "sum", columns: ["Qty", "Amount"] });
// Inside each region, the average of each product (the list must be sorted by Product within the region).
session.subtotal("Sales", "A1:D27", { by: "Product", fn: "average", columns: ["Qty"], replace: false });
session.subtotalRows("Sales", "A1");               // { rows: [5, 9, 10], grand: 10 }
session.removeSubtotals("Sales", "A1");            // Remove All: the rows and the groups go; returns how many rows
```

- **Options** (`SubtotalOptions`). `by` is the column whose changes start a new group and `columns` the ones to work out, each by letter (`"C"`) or by the text of its heading (`"Amount"`). `fn` is `sum` (the default), `count`, `countNums`, `average`, `max`, `min`, `product`, `stdDev`, `stdDevp`, `var` or `varp` (Excel's `SUBTOTAL` numbers 9, 3, 2, 1, 4, 5, 6, 7, 8, 10 and 11). `replace` (the default) takes the subtotals that are there out first; `replace: false` adds a level inside the groups there are, which is how nested subtotals are made. `pageBreaks` puts a page break between groups, `summaryBelow: false` puts each subtotal over its rows (this is the sheet's outline setting, so it applies to its other groups too), and `grandTotal: false` leaves out the total of the whole list. `sort` (`true`, `"ascending"` or `"descending"`) sorts the list by the `by` column first, in the same undo step (Excel leaves that to you), and `convertTable: true` lets the command work on a table (see below).
- The list. The range's first row holds the headings; a single cell stands for the block of data around it. A change is any difference in what the column shows, so sort the list by that column first (`session.sort`). The label goes in the `by` column (`North Total`, `Grand Total`, `North Average`…, `(blank) Total` for an empty cell), the subtotal rows are bold, and a sum, average, largest, smallest or product takes the number format of the first row of its column.
- What it makes. Every row of a group is one level deeper than before and its subtotal row is where the group's summary sits. The formulas are relative (`SUBTOTAL(9,C2:C4)`), the grand total reads from the first row to the last row of the list, and the whole run is one undo step.
- `SUBTOTAL`. Besides its 11 functions, `SUBTOTAL(101…111, …)` leaves out hidden rows (rows folded in a group, hidden by hand or by a filter) while `SUBTOTAL(1…11, …)` leaves out only the rows a filter hid, as in Excel. A row that a collapsed group folded away counts as hidden by the group, not by a filter, even inside the filter's range, so `SUBTOTAL(9, …)` still adds it. Both leave out cells that hold a `SUBTOTAL` themselves, so a subtotal of subtotals (or a grand total) does not count anything twice, and both are worked out again when rows are hidden or shown.
- Tables. Excel greys the Subtotal button out over a table. Here the command refuses, with a message that names the table and says to turn it into a range first. With `convertTable: true` (the dialog says so, and OK does it) it converts the table for you in the same undo step: the table becomes a plain range (formulas that named it, `Orders[Qty]`, get plain ranges; its slicers and timelines go, as when you convert a table), a totals row stays under the list outside the subtotals, and Undo brings the table back. Another table beside the list, in rows that subtotals would push apart, is refused (rows go in whole).
- A table's totals row takes the function of each column, as Excel's drop-down in that row does: `session.setTableTotalsFunction("Orders", "Qty", "average")` writes `SUBTOTAL(101, Orders[Qty])` (`sum` 109, `count` 103, `countNums` 102, `max` 104, `min` 105, `stdDev` 107, `var` 110; also `product`, `stdDevp` and `varp`), `"none"` empties the cell and `"=…"` takes any formula. The 100s leave out the rows the table's filter hid and the ones hidden by hand. `session.tableTotals("Orders")` says what each column works out. Excel writes `totalsRowFunction` for the eight it has in its list and `custom` for the rest.
- Merged cells. A merged label down the group column (Region, merged over its rows) names every row it covers, and merges that lie inside one group, or across columns in one row, go along with their rows. A merge that a subtotal row would have to cut through (rows across two groups, or rows of the sheet beside the list: rows go in whole) is refused, naming the merge, as is one that runs past the list's heading or last row; unmerge it first. Taking subtotals out (Remove All) is refused the same way when a merge lies across a subtotal row. Sorting first (`sort`) refuses merged cells, as sorting does.
- Pivot tables. A list over a pivot table is refused (Excel greys the button out; a pivot table has subtotals of its own, set in its dialog), and so is Remove All there; the menu item is greyed out when the active cell is in a pivot table. A pivot table lying across the rows that subtotals would push apart (beside the list) is refused. One above or below the list moves with its rows, and its cells, `GETPIVOTDATA` formulas that point at it included, are not touched but for the move.
- Limits. There is no limit on the number of groups. All the subtotal rows go in as one operation (`insert_row_runs`: the rows below are shifted once, not once for each subtotal, and the sizes and levels are set in one pass too), so a list of 40,000 rows in 8,000 groups takes about two seconds, and taking the subtotals out again (`delete_row_runs`) is as fast. Groups nest seven deep.
- **The dialog** (Data > **Subtotal…**) has Excel's choices: *At each change in*, *Use function*, *Add subtotal to* (the columns), *Replace current subtotals*, *Page break between groups*, *Summary below data*, *Grand total*, and **Remove all**, and one more, *Sort the list by this column first*. Over a table it says the table will be turned into a range; over a pivot table the menu item is greyed out.
- **In Excel files** the subtotal rows are formulas `SUBTOTAL(9,C2:C4)` and the groups are row outline levels (`outlineLevel`), with *Summary rows below detail* in the sheet's outline properties; Excel's own Data > Subtotal can remove or redo them. A merged label keeps its merge (shifted to its own rows), and a converted table is not a table in the file. LibreOffice works out the same numbers (checked with nested subtotals, subtotals above, folded rows, merged labels, a converted table with a totals row) and keeps the rows, levels, merges and where the summaries sit. File 41 of the check kit holds a converted table, merged labels, a pivot table below the list and a table's totals row with a filter.

## Sparklines

A sparkline is a tiny chart in a cell. A group of them shares one look, and each is a cell and the row or column of cells it draws.

```ts
session.addSparklines("Trends", { type: "line", location: "J2:J7", data: "B2:I7", markers: true, high: true, highColor: "#16a34a" });
session.addSparklines("Trends", { type: "column", location: "K2:K7", data: "B2:I7", negative: true, min: "group", max: "group" });
session.sparklineAt("Trends", "J2");           // { group, item: { cell: "J2", source: "Trends!$B$2:$I$2" } }
session.sparklineValues("Trends", "J2");       // [5, 7, 6, 9, …] with null for a cell with no number
session.sparklineShape("Trends", "J2", 100, 24);   // the points, bars and dots, for drawing at that size
session.updateSparklines("Trends", group.id, { color: "#336699", emptyAs: "span" });
session.clearSparklines("Trends", "J2:J3");
```

- Where and what. `location` is a column of cells with a row of `data` for each, a row of cells with a column of data for each, or one cell with one row or column. What a sparkline draws is kept like a chart's references, so it follows inserted rows and columns and renamed sheets, and goes blank when its data is deleted.
- **Kinds and options** (`SparklineGroup`): `line`, `column` or `winloss`; `color` and `negativeColor`; dots on every point (`markers`) or on the first, last, high, low or negative points, each with its colour; `lineWeight`; empty cells as a gap, zero or joined across (`emptyAs`); `showHidden`; `rightToLeft`; a line along zero (`showAxis`); and the axis `min` and `max` as numbers or `"group"` for the least or most of every sparkline in the group. Colours left out are Excel's.
- Drawing. `layoutSparkline` works out the shape from the numbers and a size, `sparklineSvg` turns it into an `<svg>`, and the grid, the print preview and the printed page all draw that. Bars grow from zero; a line fills the cell from its least to its most.
- A date axis. `dateAxis` is a row or column of dates (one for each point of the data, written like the data: `"B1:I1"` when you give it, kept as `Sheet1!$B$1:$I$1`). With one, the points sit where their dates put them, in date order, so a long wait shows as a long stretch of line (or a gap between bars, which are as wide as the smallest gap between two dates allows); a point whose date is missing isn't drawn, and the dates follow inserted rows and columns and renamed sheets like the data does. In the dialog, tick **Plot the points by date** and say which cells hold the dates.
- Theme colours. A colour is `#rrggbb` or a colour of the workbook's theme: `{ theme: 4, tint: -0.5 }` is Accent 1, 50% darker (`theme` 0 to 11 counts light 1, dark 1, light 2, dark 2, then accents 1 to 6, then the hyperlink and followed-hyperlink colours; `tint` from -1 darker to 1 lighter). `axisColor` colours the line along zero. The colour is looked up when the sparkline is drawn, in the workbook's `themeColors` (ten `#rrggbb`, or twelve with the hyperlink colours; Office's own palette without it, and Office's hyperlink colours `#0563c1` and `#954f72` when the palette has ten), so a sparkline follows the theme. The dialog shows each colour box with a *colour of the theme* choice and a shade (Normal, Lighter 80%, 60%, 40%, Darker 25%, 50%) like Excel's colour picker.
- The `SPARKLINE` function. `=SPARKLINE(A2:H2, {"charttype","column";"color","red"})` draws a chart in the cell the way Google Sheets does: `charttype` (`line`, `column` or `winloss`), `color`, `color2` or `negcolor`, `highcolor`, `lowcolor`, `firstcolor`, `lastcolor`, `axis`, `axiscolor`, `rtl`, `linewidth`, `ymin`, `ymax` and `empty` (`"zero"`); colours are any of the 148 names CSS has (`red`, `cornflowerblue`, `rebeccapurple`…, in any case), `#rgb` or `#rrggbb`. The options can also be two columns of cells. The cell holds empty text and the chart follows the data. `"charttype","bar"` draws Google's stacked bar: one segment for each positive number, in `color1`, `color2`, `color3`… (Pli's own defaults when left out), the whole width standing for the total or for `max` if that is more, running right to left with `rtl`. Data of two columns (x, then y) places each point by its x on the line and column charts, and `xmin` and `xmax` fix the ends of the x axis (points outside are left out). `nan` is `"ignore"` (the default: text in the data leaves a gap) or `"convert"` (text counts as zero); `empty` is `"zero"` or a gap.
- Printing. A cell with a sparkline is part of what prints, even if it holds nothing else.
- **In Excel files** they are `x14:sparklineGroup` elements, which Excel 2010 and later read: colours as `rgb` or as `theme` with a `tint` (`<x14:colorSeries theme="4" tint="-0.5"/>`), the date axis as `dateAxis="1"` with the dates in an `xm:f` after the colours. A workbook with theme-coloured sparklines (or its own palette) also gets a theme part (`xl/theme/theme1.xml`) so that a theme colour means the same colour in Excel. LibreOffice reads and writes them (type, cells, data, colours with their themes and tints, flags, line weight); it keeps the date axis switch but not the range of dates, so a file saved by LibreOffice has lost the dates. Excel has no `SPARKLINE` function, so a cell with one shows `#NAME?` there.

## Printing

A sheet prints the way Excel prints it: its print area (or every cell with something in it, and the charts and pictures), cut into pages where one is full or where a break was made, with the title rows and columns repeated.

```ts
session.setPageSetup("Report", { orientation: "landscape", paper: "a4", fit: { wide: 1, tall: 0 }, gridlines: true,
  header: { left: "&A", right: "&D" }, footer: { right: "Page &P of &N" } });
session.setPrintArea("Report", ["A1:H120"]);
session.setPrintTitles("Report", { rows: "1:1", cols: "A:A" });
session.setPageBreak("Report", "row", 40);               // a break after row 40
const layout = session.printLayout("Report");            // { paper, margins, scale, areas, pages: [{ number, range, titleRows?, titleCols? }] }
const page = session.printPage("Report", layout.pages[0]!);   // { html, width, height, main, origin, header, footer }
const { bytes } = await printToPdf(session, "Report");   // the printout as a PDF file, without a browser
```

- **Page setup** (`PageSetup`): paper (`letter`, `legal`, `tabloid`, `executive`, `a3`, `a4`, `a5`), landscape, a `scale` of 10 to 400 percent or `fit` to a number of pages wide and tall (0 for as many as needed; it never enlarges, and breaks you made are then ignored), margins in inches, centring, gridlines, row and column headings, pages going over before down, black and white, the first page number. Anything that is Excel's default is not kept.
- Pages. Rows and columns that are hidden take no room. Each print range starts a new page. Title rows and columns repeat on every page after the first, and on the first too when they lie above or left of the print area. A manual break (`rowBreaks`, `colBreaks`: after this row or column) goes with its row or column when rows or columns are inserted or deleted, as the print area and titles do.
- **Headers and footers** hold Excel's codes: `&P` page, `&N` pages, `&D` date, `&T` time, `&F` file name, `&A` sheet name, `&B` `&I` `&U` `&S` for bold, italic, underline and strikethrough, `&14` for a size, `&"Font,Style"`, `&Krrggbb` for a colour, `&&` for an ampersand. There can be another for the first page and for even pages.
- **`printPage`** gives a page as a table with the sizes of its cells in points, with the look of its cells (conditional formats and table styles too), the repeated titles, and the gridlines and headings it prints, and where its cells sit so a picture or chart can be put over them. The grid's preview does that, and the page it prints is made of the same pieces.
- Text running on. Text that is wider than its cell runs on over the empty cells beside it on paper, as it does on screen: left-aligned text to the right, right-aligned text to the left, centred text both ways, up to the next cell that has something in it or the edge of the page (the print range). It is laid over the cells as a box, so the empty cells' fills and lines still print under it. With no print area, text that runs past the last cell with anything in it is part of what prints, so the sheet gets the columns it needs. `printPage(...).overflow` lists the cells whose text runs on (`row`, `col`, `side`, the `from` and `to` columns it reaches, and the room it has in points). How wide text is on paper is worked out from Calibri's letter widths (`textWidthPt`), so another font can differ a little; a cell whose text is within about 15% of fitting is given the room too, which costs nothing when the text fits.
- **Comments** (notes). `comments: "end"` prints every note on pages of their own after the sheet ("Cell A1: the note", in cell order, numbered on from the last page; `layout.pages[i].notes` holds the notes on such a page), the ones that aren't showing too, as Excel does. `comments: "sheet"` ("as displayed on sheet") prints only the notes that are kept showing (right-click a cell > Show/Hide Note; `session.showNote`), each as its box where it sits on the sheet: the size, place, look and author it has (`printPage(...).notes`: `x`, `y`, `width`, `height` in points from the first cell of the page, with `runs` and `author`). A note whose box lies over the page's cells is printed there, cut off where the page's cells end (the print area, a page break or the edge of the last cell), so a box that sticks out past the print area is printed only as far as the area goes, and one across a page break is printed on both pages, each with its own part. Boxes never make the sheet bigger, and a note on a hidden row or column isn't printed. In the XLSX file this is `cellComments="asDisplayed"` (and `atEnd`), and which notes show is the `x:Visible` of their boxes.
- Errors. `errors: "blank" | "dash" | "na"` prints a cell that holds an error as nothing, `--` or `#N/A` (the Page Setup "Cell errors as" list: displayed, &lt;blank&gt;, --, #N/A); left out, errors print as they show. The screen is unchanged.
- Black and white and draft quality. `blackAndWhite` prints everything black on white: no fills, shading, colour scales or coloured text, black lines (a table's or conditional format's colours too), the header and footer without their colours, sparklines in black, and charts and pictures in shades of grey (not Excel's patterns). `draft` leaves out the gridlines and the graphics (charts, pictures, slicers, sparklines, pictures in cells and in the header and footer, which also take no room in the print range); text, fills and borders still print. Both are in File > Page setup…, and in the XLSX `pageSetup` as `blackAndWhite="1"` and `draft="1"`.
- Pictures in headers and footers. `setHeaderFooterPicture(sheet, "header" | "footer" | "firstHeader" | "firstFooter" | "evenHeader" | "evenFooter", "left" | "center" | "right", picture)` puts a PNG, JPEG or GIF where the `&G` code (Excel's `&[Picture]`) is in that part's text, and adds the code if the text has none (taking the picture away takes the code away, and `null` is how). `headerPictureFrom(src, { width?, height?, scale? })` works out the size on paper in points from the picture's pixels (or a percent, or one side with the other following), `scaleHeaderPicture(picture, { percent | width | height, lockAspect })` resizes one, and a picture may have a `crop` (fractions from each side) and `grayscale`. They are drawn in the print preview and on paper, in black and white with the setting, and left out in draft quality. File > Page setup… adds a picture file to a part of the header or footer and sizes it. In the XLSX file they are `legacyDrawingHF`, a drawing whose shapes are named for where they go (`LH`, `CH`, `RH`, `LF`, `CF`, `RF`, with `EVEN` or `FIRST` added for the even pages and the first page), each with an `o:spid`, the `type="#_x0000_t75"` of its shape type and a `v:imagedata` that points at a picture file in `xl/media`, written the way Excel writes them. A sheet's two legacy drawings, the notes' and the header's, have blocks of shape numbers of their own (the drawing's `idmap`), so that no shape number is used twice in a sheet, and a header's text keeps its `&G` code when it is set again, since a picture without one is not shown. The package check (`excel-check/lint.ts`) tests all of this: shape names, unique `o:spid`s inside the `idmap` blocks, the shape type, the picture relationships, and a `&G` for every picture.
- Page break preview. View > **Page break preview** (the `pageView` the grid is given) outlines the print ranges in blue with what is outside them dimmed, writes **Page n** over each page, and draws the breaks: dashed where a page is full, solid where one was made. Drag a break to another row or column to move it (`movePageBreak`; dragging a dashed one makes it a solid one at the new place, and the page after it is laid out again), drag a range's edge to change the print area (`movePrintAreaEdge`), and right-click for Insert page break (above the row and left of the column of the cell: `insertPageBreakAt`), Remove page break, Reset all page breaks, Set print area and Clear print area. A sheet set to fit on pages ignores breaks, so a break made or moved on one turns the fitting into the scale it came to. Each change is one undo step.
- Print preview and Print. File > **Print…** (Ctrl or Cmd+P) shows the pages as they come out, with the buttons **First page**, **Previous**, **Next** and **Last page**, a **Page** box to go to one and **One page at a time** (PageUp, PageDown, Home and End go through the pages too). **Download PDF** makes the printout as a PDF file and saves it (through `onDownload` when that is given); **Print** appears when `onPrint` is, and gives the host the same PDF (and the pages as HTML) for its own print service. Nothing opens the browser's print dialog unless `browserPrint` is on, which adds **Print with the browser…**.
- PDF files. `printToPdf(session, sheet, options)` makes the printout as a PDF without a browser (it is `async`, and is the same file the preview's buttons make): `{ bytes, pages, warnings }`. It draws what `printLayout` and `printPage` lay out: the cells' fills, lines (double, dashed and dotted too), text (clipped at its cell, running on over empty cells, wrapped, aligned, indented, with underline and strike), gridlines and headings, data bars, merged cells, sparklines, pictures in cells and over the sheet (crop, mirror, turn, brightness, contrast, grey and artistic effects, a border and a flat shadow), charts, notes (as boxes, or listed at the end), headers and footers with their pictures, links, and the paper, margins, scale, centring and first page number of the setup, in black and white or draft quality when it says so. Options: `pages` (only these pages, by their place), `date` (the date in the file, which makes the same sheet always make the same bytes), `title`, `author`, `fonts` and `rasterize`. Text is set in the standard PDF fonts, stretched to the width Calibri would give it (so the decisions about text running on hold), and `fonts` embeds TrueType files for another script. The icons of icon sets are drawn as paths in the file (sharp at any size, in Node too, and grey in black and white), and so are charts of the common kinds: column, bar, line, area, scatter, pie and doughnut, with their title, legend, axes and gridlines, stacked or 100% stacked, in the series' colours. Any other chart (3-D, radar, bubble, stock, surface, the newer kinds, a logarithmic or reversed axis) is asked of the host: `rasterize({ kind: "chart", ... })` is given the chart and answers with pixels (`<PliSheet>` does it with the browser's canvas, drawn on paper's colours); without it that chart is a frame with its title and `warnings` says so. The drawing is `chartPdfItems` and `svgToPdfItems`, and the PDF writer has a `path` item (move, line, curve, close, with fill, stroke, dash and clip). The PDF writer is `toPdf` of `@pli.dev/docs`.
- Checked against LibreOffice. Turned into a PDF there, files with the setups above come out on as many pages as `printLayout` says (the default, landscape, A4, legal, scales, margins, fit to pages, print areas, breaks, repeated rows and columns, page order), and a header, footer, page number and row range on each page are where `printLayout` puts them. LibreOffice does not read the comments, errors, draft or black and white settings from a file (it writes its own defaults back), so those are checked as XLSX attributes and by Pli's own tests, and what LibreOffice does check is that such a file opens, prints the same pages of cells and keeps the rest of its setup (and the same for a file with pictures in its header). The Excel check kit has printing files for checking it in Excel by hand (12 and 29). The PDF Pli writes is opened by LibreOffice (same page count) and read by PDFKit, which finds on each page the header, footer, row range and numbers `printLayout` says, and a sheet with notes and pictures in its header (two legacy drawings) opens there too. LibreOffice drops pictures in headers when it saves, so those are checked by the package check instead.

## Protection

Protection keeps people from changing cells by accident. It is not security: the workbook is a file that anyone can open and edit, and a password only stops the protection being taken off from the grid.

```ts
session.setStyle("Form", "B2:B4", { locked: false });          // the cells people fill in
session.setStyle("Form", "C2", { hideFormula: true });         // its formula isn't shown while protected
session.protectSheet("Form", { password: "pli", allow: ["formatCells", "sort", "selectLockedCells", "selectUnlockedCells"] });
session.setCell("Form", "A1", "x");                              // throws a ProtectionError: A1 is locked
session.unprotectSheet("Form", "pli");                           // throws if the password is wrong
session.protectWorkbook({ password: "wb" });                    // the sheets can't be added, deleted, renamed, moved or hidden
session.bypassProtection(() => session.setCell("Form", "A1", "the application's own change"));

session.setLocked("Form", "C:C", false);                         // the whole column: its cells, and cells made in it later
session.setFormulaHidden("Form", "D:D", true);                   // the formulas of the whole column D are hidden once protected
session.addEditRange("Form", { name: "Quantities", ranges: ["B2:B9"], password: "ed" });
session.unlockEditRange("Form", "Quantities", "ed");             // for as long as the session lives
session.setUser({ id: "u42", roles: ["finance"], accounts: ["S-1-5-21-1-2-3-1001"] }); // who is using the sheet (your app knows)
```

- What is refused. The session checks every change (`ProtectionError`, a `PliError` with a message that says what to do), so the grid, a script and your own code all meet the same rules, and undo can't get round them: protecting or unprotecting forgets the undo history, as Excel does.
- Locked cells. Every cell is locked until `locked: false`, even an empty one that doesn't exist yet. Typing, clearing, pasting, filling, moving and sorting cells that include a locked one are refused, and so is deleting a row or column (see below). What is pasted, filled or moved onto an unlocked cell doesn't change whether it is locked, and unlocking cells can't be done while the sheet is protected.
- **What can be allowed** (`allow`, as Excel's dialog lists it): select locked cells, select unlocked cells (both on unless taken out), format cells (conditional formats and merging too), format columns, format rows, insert columns, insert rows, insert links, delete columns, delete rows, sort, use filters (and slicers), pivot tables (changing and refreshing them) and scenarios (kept for Excel's sake), and edit objects (charts, pictures, slicers and notes). Freezing panes and defined names are never refused. Data validation and tables (other than filtering and sorting one) can't be changed on a protected sheet, and a filter can be used but not made or taken off.
- The Review menu. Review (in the menu bar, and as a **Review and protect** button in the toolbar) holds the notes commands (new or edit, delete, show or hide, show or hide all, previous and next) and everything that protects: Protect sheet… / Unprotect sheet…, Protect workbook structure… / Unprotect workbook…, Allow edit ranges…, Lock edit ranges again (closes the password ranges that were opened), and Spelling… and Check accessibility (see [Review](#review-spelling-and-accessibility)). Every item is a button in a menu: Left and Right move along the menu bar, Up and Down between items, Enter chooses, Escape closes. In Excel, Review also has threaded comments and track changes; those come with the comments and collaboration shared by every editor.
- When selecting is limited. If a sheet doesn't allow selecting locked cells, clicks and arrow keys don't go onto them, and Enter and Tab go from one unlocked cell to the next.
- Deleting rows and columns. As in Excel, `deleteRows` and `deleteColumns` (the permissions) are not enough: every cell of the rows or columns has to be changeable, the empty ones too, which are locked unless a row, column or the sheet was unlocked. So a row you just inserted can't be deleted again (Excel lets people insert rows they can't delete), and a row or column can be deleted only when you unlocked it as a whole (`setLocked(sheet, "10:10", false)`) or a range of whole rows that this person may edit holds it. The refusal says what Excel says: "The cell or chart you're trying to change is on a protected sheet". A role in `editLocked` is held to the permission only. Rows and columns that pass through a table can't be deleted at all while the sheet is protected, since a protected sheet can't resize a table, whoever asks (Excel's rule here is a guess, see Not there yet). Merged cells count by their cells, so the covered ones have to be unlocked too. Pli has no array formulas whose cells can't be changed apart.
- Hidden formulas. On a protected sheet the formula bar shows nothing for a cell that hides its formula, a copy made here brings its value and not the formula, editing it starts empty, `FORMULATEXT` of it is `#N/A` (as in Excel's help), and find in formulas skips it. `session.formulaHidden(sheet, address)` says which. Rows, columns and the whole sheet can carry it (next section).
- Passwords are kept as Excel keeps them (a salted SHA-512 spun 100,000 times, which takes about a third of a second to check) and never as the password. Old files' 16-bit password hashes are read and checked too. Without a password anyone can unprotect.
- Applications can set protection aside for their own changes with `bypassProtection(fn)`, which lasts only as long as `fn`.
- In Excel files. A cell's lock is part of its style, a sheet's protection is `sheetProtection` with what is allowed, and the workbook's is `workbookProtection` with `lockStructure`. All are read and written, with the password hash as Excel writes it. Ranges that people may edit (`protectedRanges`, with `sqref`, `name` and a password) and the locks of columns and rows (the `style` of a `col` and the `s` of a `row`) are read and written too. See the sections below.

### Locks that columns and rows carry

Excel locks or unlocks a whole column, row or the whole sheet by giving it a style, and cells made in it later are made with that style. Pli's cells are sparse, so a cell that says nothing about its lock takes its row's, then its column's, then the sheet's, and is locked when none of them says.

- Model. `columns[A].locked` and `rows[3].locked` (a row wins over a column), and `unlocked: true` on the sheet for "select all, then unlock". A cell's own `s.locked` is kept only where it differs from what its row, column and sheet say, so `true` shows up only inside something unlocked.
- Setting it. `session.setLocked(sheet, "B:B", false)` (and `setStyle(sheet, "B:B", { locked: false })`, or Format > **Locked** with a whole column, row or the whole sheet selected) sets the column, row or sheet, and the cells that exist take it. Where a row and a column cross, the one set last wins. It is one undo step, and refused while the sheet is protected, as locking single cells is.
- Inserting. Rows and columns inserted next to one that carries a lock take the same, as Excel gives them its format. Cells in an inserted row of an unlocked column are unlocked through the column.
- Checks. Every refusal looks at the lock a cell has this way, empty cells included: typing into `B500` of an unlocked column works on a protected sheet, and `A500` does not. `isLocked`, `canEdit` and `editBlock` answer for any address. Large ranges (a whole column) are checked exactly without going through every cell.
- Excel files. `<col style>` and `<row s customFormat>` point at a style with `<protection locked="0"/>`; the cells written in them get the lock they have, as Excel does. A sheet that is unlocked as a whole is written as columns 1 to 16384 with that style, and read back as `unlocked`.

### Hidden formulas that columns and rows carry

Like locks, Excel's Hidden (Format Cells > Protection) can be set on a whole column, a whole row or the whole sheet, and cells made later take it. A cell that says nothing hides its formula (or not) as its row says, then its column, then the sheet.

```ts
session.setFormulaHidden("Form", "D:D", true);        // column D, and cells made in it later
session.setFormulaHidden("Form", "8:8", true);        // row 8 (a row wins over a column)
session.setFormulaHidden("Form", "A1:XFD1048576", true); // the whole sheet; false in a column or row shows them again
session.setStyle("Form", "D:D", { hideFormula: true }); // the same
session.hidesFormula("Form", "D500");                  // true: an empty cell would hide a formula typed into it
session.anyFormulaHidden("Form", "D:D");               // exact and quick for a whole column or row: only cells that exist can hold a formula
```

- Model. `columns[D].hideFormula`, `rows[8].hideFormula`, and `hiddenFormulas: true` on the sheet. A cell's own `s.hideFormula` is kept only where it differs from what its row, column and sheet say (`false` shows up only inside something that hides). It is one undo step, refused while the sheet is protected (as locking is), and rows and columns inserted next to one that hides take it.
- Whole ranges. The checks the grid makes (a copy, the formula bar, editing) never go through a whole column cell by cell: `anyFormulaHidden` looks at the cells that exist.
- Excel files. Written as the `hidden` flag of the `<protection>` in the style of a `<col>` or `<row>` (and of the cells in them, which carry their own style in Excel), read back the same way. A row has one style for all its cells, so a row that hides formulas also says its lock: where it crosses a column of its own lock, empty cells there take the row's, as in Excel.

### Ranges that people may edit

Excel's Allow Edit Ranges. A range is a title (unique on the sheet), one or more A1 ranges, and optionally a password and roles. They count only once the sheet is protected, and can only be changed while it isn't.

```ts
session.addEditRange("Form", { name: "Quantities", ranges: ["B2:B9"], password: "ed" });
session.addEditRange("Form", { name: "Open", ranges: ["E2:E9"] });                        // anyone
session.addEditRange("Form", { name: "Finance", ranges: ["D2:D9"], permissions: ["finance"] }); // only that role
session.updateEditRange("Form", "Quantities", { password: null });
session.deleteEditRange("Form", "Open");
session.unlockEditRange("Form", "Quantities", "ed");   // throws if it is wrong; nothing of the password is kept
session.lockEditRanges();                                // close the ones that were opened
```

- What it allows. A locked cell in a range can be changed by anyone when the range has no password and no roles, by someone with one of its roles, or by someone who gave its password (once; it is remembered until `lockEditRanges`, the sheet is unprotected, or a workbook is loaded). A range with roles and no password refuses everyone else, and says so. Only the cell's content is opened: formatting, inserting and the rest still follow what the sheet allows.
- In the grid. Typing, pasting or editing in a cell that a password range holds opens a password prompt; a wrong password says so. Review > **Allow edit ranges…** lists the ranges, adds, modifies and deletes them (while the sheet is unprotected). The `ProtectionError` carries `editRange` (`{ sheet, name }`) when a password would open the cell, so your own interface can ask for it too.
- Rows and columns. A range follows inserted and deleted rows and columns like a merged range does, and goes when all its cells do.
- Excel files. Written as `protectedRanges` with `sqref`, `name` and the password hash, read back with 16-bit and SHA-512 passwords. Excel's own way to name people (`securityDescriptor`, Windows accounts) is read and written too: see [Windows accounts](#windows-accounts) below, and [Who may do what](#who-may-do-what) for how roles are written.

### Windows accounts

Excel's Permissions button on Allow Edit Ranges names Windows accounts that may edit a range without its password (and, with Deny, accounts that may not). Excel keeps them in the range's `securityDescriptor`, written in SDDL: `O:WDG:WDD:(A;;CC;;;S-1-5-21-…-1001)` allows that account (`A`) to edit (`CC`), `D` denies. Pli keeps no accounts and has no Windows directory to look names up in, so the application supplies the person's security identifiers (SIDs) and Pli matches them as roles:

```ts
session.setUser({ id: "ada", accounts: ["S-1-5-21-1004336348-1177238915-682003330-1001", "S-1-5-21-1004336348-1177238915-682003330-513"] }); // the person and the groups they belong to
// or <PliSheet user={{ id: "ada", accounts: [...] }} />
session.addEditRange("Form", { name: "Mine", ranges: ["B2:B4"], permissions: ["sid:S-1-5-21-1004336348-1177238915-682003330-1001"], denied: ["sid:S-1-5-21-1004336348-1177238915-682003330-1002"] });
```

- Mapping. An account that is a SID (or SDDL's short name for a well-known group: `WD` Everyone, `AU` Authenticated users, `BA` Administrators, `BU` Users…) counts as the role `sid:S-1-5-21-…`. Everyone (`sid:S-1-1-0`) is every person, signed in or not; Authenticated users (`sid:S-1-5-11`) is every person `setUser` was given. A name that is not a SID counts as `account:CORP\ada`, matched ignoring case, for your own use (Excel files only name SIDs). They are ordinary entries of an edit range's `permissions` (who may edit without the password) and `denied` (who may not even then, as Excel's Deny: they need the password if there is one). Deny wins. Everything else about edit ranges is as for roles: a password, `lockEditRanges`, rows and columns following.
- In Excel files. The `sid:` entries are written as the range's `securityDescriptor` (`O:WDG:WDD:`, the denying entries first, then the allowing ones; a range that only denies lists Everyone as allowed, as Excel needs). On reading, the simple allow and deny entries `(A;;CC;;;SID)` become `permissions` and `denied`. The descriptor as read stays on the range (`securityDescriptor`) and is written back exactly as it was while the accounts still agree with it; if they were changed in Pli it is written afresh. Entries Pli doesn't read (conditions, audit entries, other rights, an owner) are kept in that text and ignored. A descriptor that names nobody Pli can read leaves the range with no one but its password, with a warning. A range that names only roles of Pli's own and has no password is still left out of Excel's list.
- Not security. The accounts come from your application and the file is open to anyone. As with roles, this is for your own rules, not a lock.

### Who may do what

Pli keeps no accounts. Your application knows who is using the sheet and tells Pli: an id and the roles it gives that person. The same `{ id }` shape is what comments use for `PliUser`, and a `PliUser`'s core `role` (`viewer`, `commenter`, `editor`) counts as one of the roles.

```tsx
<PliSheet session={session} user={{ id: "u42", roles: ["finance"] }} />
// or session.setUser({ id: "u42", roles: ["finance"] }), or new SheetSession(wb, { user })

session.protectSheet("Form", {
  allow: ["selectLockedCells", "selectUnlockedCells"],        // everyone
  roles: { formatCells: ["designer"], sort: ["analyst", "designer"] }, // and these roles may also
  editLocked: ["owner"],                                       // may change locked cells
});
session.protectWorkbook({ roles: ["admin"] });                // may change the structure
```

- Roles are matched ignoring case, and `user:` and a person's id names one person (`permissions: ["user:ada"]`). A protected sheet's `roles` add to `allow` for the person using the sheet; `editLocked` lets a role change the content of locked cells without unprotecting; neither changes whether cells are locked, which still needs the sheet unprotected.
- Enforced by the same check as the rest: the grid, a script and your own code meet it, `session.can(sheet, permission)` and `canEdit` answer for the current person, and undo can't get round it: changing the person (or closing opened ranges) while sheets are protected forgets the undo history, as protecting does.
- Saved in the workbook JSON (`protection.roles`, `protection.editLocked`, `editRanges[].permissions`, and `protection.roles` on the workbook's), and checked on loading.
- Excel files. Excel has no roles (its Windows accounts are above). The password-based form is what Excel gets: a range with roles *and* a password is written as that password range; a range with roles and no password is left out of Excel's list, so its cells stay locked in Excel (Excel would otherwise let everyone in). The roles themselves, and those ranges, are written as a Pli extension in the sheet's and workbook's `extLst` (`urn:pli:sheets`), which Excel ignores and drops when it saves, and Pli reads back. Roles are for your application's own rules, not security: anyone can open the file and take the protection off.

## Review: spelling and accessibility

The **Review** menu has **Spelling…** (F7) and **Check accessibility**, next to the notes and protection commands. Threaded comments are in the Review menu too (**Comment**, **Comments panel**, **Convert to note**, **Convert note to comment**) when `comments` is on: see [Collaboration](/sheets/collaboration/#comments). Excel's track changes have no counterpart in cells; [what takes their place](/sheets/collaboration/#track-changes) is described there.

**Spelling.** A dialog steps through the words that are not in the dictionary, selecting the cell each is in and showing the word in its text, with the usual choices: **Ignore once**, **Ignore all**, **Add to dictionary**, **Change** (to the box, which starts with the best suggestion, or one picked from the list; double-click a suggestion to change at once) and **Change all**. It checks the selection when more than one cell is selected, otherwise the sheet, and a list in the dialog switches to the sheet or the whole workbook. Every change is an undo step; **Change all** is one step for every cell it touches. It reads typed text only: formulas and their results, numbers, cells a pivot table draws and checkboxes are left alone, and so are words in capitals, words with digits and web and email addresses (the options `ignoreUppercase`, `ignoreNumbers`, `ignoreAddresses` of `SpellChecker`).

The dictionary is the host's. `<PliSheet spellDictionary={...}>` takes a list of words (an array, a `Set`, or one string of words), or an object with `has(word)` and, if it can, `suggest(word, max)` and `words()`, such as a wrapper over Hunspell's word lists. `spellWords` gives the words people added to their own dictionary earlier and `onSpellAddWord` is called with each word they add, for you to keep. Without a dictionary a short list of common English words is used (`basicDictionary`), which is a demonstration, not a dictionary. A plural, `-ed`, `-ing`, `-ly`, `-er` or `-est` form of a dictionary word is accepted, and suggestions are the dictionary words within one or two edits, in the capitals of the misspelt word.

```ts
import { SpellChecker, findMisspellings, changeMisspelling, changeAllMisspellings } from "@pli.dev/sheets";

const checker = new SpellChecker(myWords, { custom: peoplesWords });   // or { has, suggest, words }
const found = findMisspellings(session, checker, { sheet: "Sheet1", range: "A1:D40" }); // sheet and range optional
// [{ sheet, address, word, start, end, text }, …] in reading order
changeMisspelling(session, found[0], checker.suggest(found[0].word)[0]);   // refuses if the cell changed since
changeAllMisspellings(session, found, "teh", "the");                       // one undo step
checker.addWord("Pli");  checker.ignoreAll("tpyo");
```

**Accessibility.** The check opens a panel above the grid that lists what a screen reader or poor eyesight would trip on, worst first, each with where it is (click it to go there): pictures and charts with no alternative text (errors; a chart's `alt` is written as the description of its frame in an .xlsx file and read back), tables with no header row (error, **Turn on the header row**), merged cells (warning, **Unmerge the cells**), text with less contrast than WCAG asks for against its fill (warning: 4.5 to 1, or 3 to 1 for large text; one entry for each pair of colours, **Use black text** or **Use white text**), blank rows and columns between data used as spacing (tip, **Delete the blank row**), and sheets still called Sheet1, Sheet2… (tip). **Fix all** does every fix there is, and a problem that has no fix says what to do by hand. From code: `checkAccessibility(session)` gives the list (`{ id, kind, severity, sheet, where, cell, message, hint?, fix?, object? }`), `fixAccessibility(session, issue)` fixes one and `fixAllAccessibility(session, issues)` all of them.

## Pictures

A picture is anchored like a chart: to a cell, a little way into it, with a size in pixels. It is saved in the workbook as a `data:` URI.

```ts
import { toDataUri } from "@pli.dev/sheets";

const image = session.addImage("Sheet1", { src: toDataUri(pngBytes, "png"), from: { row: 3, col: 2 }, alt: "Our logo" });
session.updateImage("Sheet1", image.id, { width: 240, height: 80 });   // moved or resized, or described with `alt`
session.fitImage("Sheet1", image.id, "B3:D6");                          // fills those cells
session.cropImage("Sheet1", image.id, { left: 0.25, top: 0.1 });        // cuts off a quarter of the width from the left and a tenth off the top
session.rotateImage("Sheet1", image.id, 90);  session.flipImage("Sheet1", image.id, "h");
session.formatImage("Sheet1", image.id, { rotation: 30, crop: null, placement: "size" });   // several of those in one step
session.copyImage("Sheet1", image.id, { sheet: "Other", from: { row: 2, col: 2 } });         // a copy, here a little way off by default
session.reorderImage("Sheet1", image.id, "back");
session.images("Sheet1");  session.deleteImage("Sheet1", image.id);
```

- What it keeps. PNG, JPEG and GIF, up to 5 MB each. `src` is checked on the way in, in a saved workbook and in an XLSX file: it must be a base64 `data:` URI whose bytes really are that kind of picture (a PNG that says it is a JPEG is refused), so a picture can't be a script or a page. Without a size a picture is its own, scaled down to fit 480 by 360; with only a width or a height the other follows in proportion.
- The grid turns other kinds the browser can draw (WebP, BMP, SVG) into PNG when they are added, and scales a heavy photo down until it fits. Pasting counts only when nothing else is on the clipboard: copying cells in Excel also puts a picture of them there, and the cells win.
- Under the charts. Pictures are drawn over the cells and under the charts and slicers; the order among pictures can be changed.
- Crop, turn and flip. A crop (`crop`) is the part of the picture's own size cut off each side, from 0 up to less than 1, leaving some of it; `width` and `height` are the size of what is left, and `cropImage` keeps the scale, so the picture gets smaller as it is cropped. `rotation` is degrees clockwise about the centre (kept between 0 and 360), and `flipH` and `flipV` mirror it before it is turned. The grid picks a turned picture by its turned shape, and its edges are dragged along its own axes. Holding **Alt** (Option) while dragging an edge or corner of a picked picture crops it instead of resizing it: pulling in cuts, pulling out gives back what was cut, a mirrored picture is cut on the side you pull, and at least 5% of the picture stays. The whole drag is one undo step.
- **How it follows its cells** (`placement`). Left out, a picture moves with its cell and keeps its size (Excel's "move but don't size"). `"size"` is "move and size with cells": it has a second corner (`to`, a cell and how far into it) and stretches when a row or column under it is made bigger or smaller, hidden, inserted or deleted. `"free"` stays where it is on the sheet whatever happens to the cells above and to its left. Choose it in **Format picture…** or from the right-click menu's **Move and size**.
- Copying. `copyImage` makes a copy on this sheet or another; in the grid Ctrl+C and Ctrl+V do the same at the active cell, and Ctrl+X moves it, each paste one undo step. Another program gets the picture itself: Ctrl+C also puts the picture on the clipboard as an image (HTML with the picture in it), which Word, Google Docs and mail programs paste as a picture, and Pli's own paste uses the picture with all of its settings.
- Keyboard. With the grid focused, **Alt+Shift+Down** picks the first picture or chart (the next one if one is picked) and **Alt+Shift+Up** the last (or the previous); **Tab** and **Shift+Tab** step round them. A picked one moves with the arrow keys, 10 pixels at a time or 1 with Ctrl or Cmd, and Shift with an arrow stretches its right and bottom edges. Escape lets go, Delete removes it and Enter opens its settings. This works for charts as well.
- Excel files. Pictures are anchors with a picture in the sheet's drawing, their files in `xl/media`, with the description as the picture's alternative text. A one-cell anchor is a picture that moves but doesn't size, a two-cell anchor with `editAs="twoCell"` moves and sizes, and `editAs="absolute"` (or an absolute anchor) neither; the crop is the picture's `srcRect`, and the turn and flips are on its `xfrm`. The border is the picture's outline (`a:ln`), the glow, shadow, reflection and soft edges are the shape's effect list (`a:glow`, `a:outerShdw`, `a:reflection`, `a:softEdge`, in the order the schema has them; a colour from the theme is read as the theme's plain colour, without its tints), and the corrections are the brightness and contrast (`a:lum`) and the grey shades (`a:grayscl`) on the picture itself. LibreOffice reads and writes the same crop, turn, flips, anchors, border, shadow and grey shades (it drops brightness and contrast when it saves). An artistic effect is Excel's own extension on the picture (`a14:imgProps`): the picture the file shows is the effect already drawn (so any program shows it), and the extension holds the original as a second file with the effect and its setting (`a14:artisticBlur radius`, `a14:artisticPencilSketch pressure`, `a14:artisticMosiaicBubbles spacing` and so on), which is what Pli reads back to get the original and the effect. The second file is what Excel itself writes there: an HD Photo (JPEG XR, `xl/media/hdphoto1.wdp`, content type `image/vnd.ms-photo`, relationship `http://schemas.microsoft.com/office/2007/relationships/hdphoto`), with the pixels of the original coded without any loss; Excel dropped the effect when the layer was a PNG. Pli writes and reads these files itself (`encodeJxr` and `decodeJxr`, plain TypeScript, see **JPEG XR** below). The picture the file shows is always a PNG Pli drew, from a PNG, JPEG or GIF alike (the pixel readers `decodeJpeg` and `decodeGif` are plain TypeScript). The original keeps its pixels exactly, transparency included, so a picture with an effect comes back from an .xlsx file as a PNG of the same pixels it was (a JPEG or GIF comes back as a PNG, not as the JPEG or GIF bytes). An HD Photo layer Excel wrote is read the same way when it is of a kind Pli reads (8 or 16 bits a channel, grey or colour, with or without alpha, any overlap, tiling and order; see **JPEG XR** below for what is not read); an effect Pli doesn't have, and an HD Photo it can't read, come in as the picture Excel drew, with a warning. LibreOffice opens such a file and writes the layer back. Only a JPEG that uses arithmetic coding or 12 bits, or a GIF too damaged to read, is written plain. A shape a picture is cropped to is its preset geometry (`a:prstGeom`, see **Crop to shape** below); LibreOffice draws the shape but writes the picture back as a shape filled with the picture, which Pli does not read as a picture.
- Border, shadow and corrections. `formatImage` (and **Format picture…**) take a `border` (`{ color, width?, dash? }`, width in pixels up to 20, dash solid, dashed or dotted), a `shadow` (`{ color?, blur?, distance?, angle?, opacity? }`), `brightness` and `contrast` (−1 to 1, 0 is left alone) and `grayscale`. They are drawn in the grid and in print preview, and are checked on the way in; null takes a border or shadow off.
- Glow, soft edges and reflection. `glow` is `{ color?, radius?, opacity? }` (a blue glow of 10 pixels at 40% by default), `softEdge` the number of pixels over which the picture's edges fade out (0 to 100), and `reflection` is `{ blur?, startOpacity?, endOpacity?, distance?, size? }`: a mirror image under the picture that starts `startOpacity` solid, has faded to `endOpacity` after `size` of the picture's height (0.01 to 1) and starts `distance` pixels below it. Set them with `formatImage` or **Format picture…** (null takes one off; Format > Picture > **Remove effects** takes all of them and the shadow off). The glow follows the picture's own shape (a PNG with see-through parts glows round what is there), the soft edges fade the picture with a mask, and the reflection turns with the picture. They are drawn in the grid, in print preview and in the picture a copy puts on the clipboard.
- Artistic effects. `artistic: { kind, level? }` runs one of Excel's twenty-two effects over the picture's pixels: `blur`, `pencilGrayscale`, `pencilSketch`, `mosaic`, `glass`, `paintBrush`, `cutout`, `filmGrain`, `photocopy`, `glowDiffused`, `glowEdges`, `lineDrawing`, `marker`, `chalkSketch`, `cement`, `crisscrossEtching`, `lightScreen`, `pastelsSmooth`, `plasticWrap`, `texturizer`, `watercolorSponge` and `paintStrokes` (`ARTISTIC_KINDS`). `level` is a whole number in the effect's own range (`ARTISTIC[kind]` has the range, the usual level and the name Excel uses; it is the number Excel's own setting holds, such as the radius of a blur). The pixels are worked in plain TypeScript (`applyArtistic`, on the readers `decodePng`, `decodeJpeg` and `decodeGif` (found by `decodeImage`) and the PNG writer `encodePng`), so the sheet, a print, a copy and an .xlsx file show the same picture for a PNG, a JPEG and a GIF, in a browser and in Node. A JPEG is shown the way the browser shows it (its EXIF orientation applied), a GIF is its first picture, and a picture the readers can't read falls back to the browser's canvas on the sheet. The picture itself is kept as it was; the effect is drawn from it (a picture is worked at 1200 pixels on its longest side at most), the corrections (brightness, contrast, grey) go on top, and picking another effect, or none, brings the original back. These are Pli's own versions of effects Excel has under the same names, close in spirit and not pixel for pixel; Pli's mosaic is a plain mosaic, where Excel's is Mosaic Bubbles. The textures (cement, texturizer, pastels, film grain) come from a fixed noise, never a random number, so a picture looks the same each time it is drawn. The setting of each effect is the attribute Excel keeps it in (`ARTISTIC[kind].attribute`); Format picture… sets it with a slider that has the effect's own range (and a number box beside it).
- JPEG XR (HD Photo, `.wdp`). `encodeJxr(rgba, options?)` writes the pixels (`{ width, height, data }`, as `decodePng` gives) as a `.wdp` file and `decodeJxr(bytes)` reads one back (null when the bytes are not one, or are one of a kind it does not read); `isJxr(bytes)` says whether bytes begin like one. Nothing is lost: a picture comes back exactly, transparency included (the alpha is a second, grey, coded picture in the file, as the reference encoder writes it; `interleavedAlpha` codes it in the same codestream instead). The usual file is a 24 bit colour picture (or 32 bit with alpha), one tile, in spatial order, with every quantizer 1 and one level of overlap between blocks, which is, byte for byte, what the reference implementation (jxrlib) writes for a lossless picture; `options` can ask for the other forms the format has (`overlap` 0 or 2, `frequency` order with an index table, `tileWidths` and `tileHeights` in macroblocks, `subband` to leave bands out and `trimFlexBits` to leave low bits out, which lose some of the picture). The reader reads all of those: spatial or frequency order, any tiling, overlap of none, one or two levels, every band, trimmed flexbits, and the quantizers of lossy files (they come out as the reference reads them), 8 or 16 bits a channel (16 is brought to 8), grey or colour (coded as 4:4:4, or as 4:2:0 with the chroma brought up to size the way the standard says), with the alpha in a picture of its own in the file or in the same codestream (and colours multiplied by the alpha are divided again). Every one of those forms has been checked against the reference implementation, in both directions: the reference reads what Pli writes to the same pixels, and Pli reads the reference's files (lossless and lossy, 8 and 16 bits, 4:4:4 and 4:2:0) to the same pixels as it does. Not read, and refused (so the picture stays as Excel drew it): colour coded as 4:2:2, more than four channels or CMYK, floating point and 32 bit numbers, rotated pictures, windowed pictures and hard tile boundaries; a file that uses a different quantizer for each tile or each macroblock is read as the standard says, but no such file has been available to check it with. It is used for the original of a picture with an artistic effect in an .xlsx file, where it is the form Excel keeps it in (and where it is as large as the lossless pixels are: much more than the JPEG a photograph came from). A 3000 by 2000 pixel picture takes a second or less each way.
- The crop tool. A picture can be put in crop mode from its right-click menu (**Crop**), from Format > Picture > **Crop**, from the **Crop picture** button at the end of the toolbar, or from the **Crop on the sheet** button in Format picture…. The whole picture shows, dimmed, behind the part that is kept, and the handles become crop marks (an L on each corner, a bar on each edge). Dragging an edge or a corner crops it (no Alt needed, though Alt still crops when not in crop mode), dragging inside the picture slides the picture under its frame (the frame stays where it is and the crop moves), and **Enter** or **Escape** end crop mode, leaving the picture picked (so does picking something else). Each drag is one undo step. **Crop to shape** (right-click, or Format > Picture) first crops from the middle to a proportion: a square, 4:3, 3:2, 16:9, 3:4, 2:3 or 9:16, **Fill the frame** (the picture fills the frame it is in, cutting what doesn't fit) or **Fit in the frame** (the whole picture, as big as fits). From code: `session.cropImageToRatio(sheet, id, "16:9")` (a number, `"w:h"`, `"fill"` or `"fit"`). The same menu then has the shapes to crop to, below.
- Crop to shape (an oval, a star, an arrow…). `shape` on a picture crops it to one of 36 of Office's preset shapes, which fill the picture's frame (what is left after a crop): the rounded and snipped rectangles (`roundRect`, `round1Rect`, `round2SameRect`, `round2DiagRect`, `snip1Rect`, `snip2SameRect`, `snip2DiagRect`, `snipRoundRect`), `ellipse`, `triangle`, `rtTriangle`, `diamond`, `parallelogram`, `trapezoid`, `pentagon`, `hexagon`, `octagon`, `plus`, `teardrop`, `heart`, the arrows (`rightArrow`, `leftArrow`, `upArrow`, `downArrow`, `leftRightArrow`, `chevron`, `homePlate`) the stars (`star4`, `star5`, `star6`, `star8`, `star10`, `star12`) and the speech bubbles (`wedgeRectCallout`, `wedgeRoundRectCallout`, `wedgeEllipseCallout`); `IMAGE_SHAPES` has Excel's name for each and the group of its gallery. Choose one from the right-click menu's **Crop to shape** (grouped as Rectangles, Basic shapes, Block arrows, Stars and Callouts, with a tick on the picture's own and **Rectangle** to take it off), from Format > Picture, or from the **Shape** list in Format picture…; from code `session.cropImageToShape(sheet, id, "star5")` (null makes it a rectangle) or `formatImage(sheet, id, { shape })`. The picture shows only inside the shape (`shapePath(shape, w, h)` is its outline as an SVG path, used as a CSS clip path on the sheet, in print preview and in the picture a copy puts on the clipboard); its border is drawn along the shape and its shadow follows it (a rectangle keeps the box shadow). The shapes are drawn with Office's adjustments and checked against LibreOffice's rendering of the same preset shapes. Yellow handles: a picked picture with a shape shows a yellow diamond for each adjustment, as Excel does: drag it to change the corner radius of a rounded or snipped rectangle, the slant of a trapezoid or parallelogram, how thick an arrow's shaft and head are, how deep a star's points are, or where a speech bubble's tail points (the arrow keys nudge a focused handle, Shift for ten pixels). From code, `shapeAdjust` on the picture holds the values by Office's guide names in Office's own units (`{ adj: 40000 }` is a corner radius of 40% of the shorter side; `SHAPE_ADJUSTMENTS[shape]` lists each shape's guides with their defaults and ranges, and the ranges that depend on the picture's proportions are applied when it is drawn), `session.formatImage(sheet, id, { shapeAdjust })` sets them (one undo step per drag), `shapeHandles` and `dragShapeHandle` are the geometry behind the handles, and changing the shape starts again from the usual adjustments. In an .xlsx file the shape is the picture's `a:prstGeom` and the adjustments are its `a:avLst` guides (`<a:gd name="adj" fmla="val 40000"/>`), read back the same way (a guide that is not a plain value, or not one of the shape's, is read as the usual one).
- Crop from the keyboard. With a picture picked (Alt+Shift+Down, Tab…), **C** puts it in crop mode. In crop mode an arrow key cuts the side it names (**Left** cuts the picture's left side), **Shift** with an arrow gives back what was cut from that side, **Alt** with an arrow slides the picture under its frame, and each step is 10 pixels, or 1 with **Ctrl** or **Cmd**. At least 5% of the picture (and 8 pixels of frame) stays. **Enter** or **Escape** end crop mode. Each key press is one undo step. A mirrored picture is cut on the side of the picture that is on the named side of the screen. Everything is announced to screen readers through a polite live region by the grid: picking a picture ("Picture 2 of 3, Our logo, selected"), going into crop mode (with the keys), each cut ("Cut the left. Cut off: left 10 percent, top 0 percent… The picture is 90 by 50 pixels.") and the limits ("The left can't be cut any more."); the picked picture is named `Our logo, crop mode` (or `selected`) for assistive technology.

## Pictures in cells

A picture can be the content of a cell, as Excel's **Place in Cell** and its `IMAGE` function make it. It is drawn inside the cell, fitted to it (kept in proportion), and so moves and sizes with it.

```ts
session.setCellPicture("Sheet1", "B2", { src: toDataUri(pngBytes, "png"), alt: "Our logo" });   // null takes it out
session.placeInCell("Sheet1", image.id);          // turns a floating picture into its cell's content
session.placeOverCells("Sheet1", "B2");           // and back, sized to the cell
session.cellPicture("Sheet1", "B2");              // the picture a cell shows, either kind, or null
session.setCell("Sheet1", "C2", '=IMAGE("https://example.com/logo.png","Our logo")');
```

- A placed picture is `picture` on the cell (`{ src, alt }`, a `data:` URI of a PNG, JPEG or GIF, checked as a floating picture is). The cell's value is the description, or empty text, so formulas, sorting, a CSV and the used range see something there, and the picture goes with the cell when it is copied, moved or sorted. Typing in the cell, or Clear contents, replaces the picture; Clear formats keeps it. A cell holds a picture, or a formula, not both. **Place in cell** in a picture's right-click menu and Insert > **Image in cell…** make one; **Place picture over cells** and **Remove picture** in a picture cell's menu take it out again. Cropping, turning and flipping are lost when a picture is placed in a cell.
- **`IMAGE(source, [alt_text], [sizing], [height], [width])`** shows a picture from an `https://` address (or a `data:` URI of a picture). Sizing 0 fits the cell and keeps the proportions (the default), 1 stretches to fill it, 2 keeps the picture's own size (cut off by the cell) and 3 uses the `height` and `width` in pixels. An address that isn't `https://` (or that has spaces) is `#VALUE!`, so a formula can't send the grid to a script or a file. The cell's value is the text that goes with it (the description, or the address): the picture isn't a value that other formulas can use.
- Pictures from the web are off by default. Opening a workbook someone else made shouldn't contact other sites, so an `IMAGE` formula whose address is on the web shows its text until the editor is told to allow it: `<PliSheet remoteImages />`. One whose `source` is a `data:` URI fetches nothing and is always drawn. In the grid, View > **Pictures from the web** turns them on for this session, a picture that has been fetched is remembered by address (so drawing the grid again doesn't ask again, and one that failed is tried again after a minute), and one that can't be loaded shows its description in a dotted box. The right-click menu's **Keep picture in cell** fetches the picture and puts it in the cell in the formula's place, so the workbook holds it. Printing draws these pictures only when pictures from the web are on (`printPage(sheet, page, { remoteImages: true })`).
- Copying and pasting. A cell with a picture copies out as an image, prints, and comes back as a picture cell when pasted from HTML.
- Excel files. `IMAGE` is written and read as the formula (`_xlfn.IMAGE`), and Excel fetches the picture itself. A placed picture is written as Excel's own picture in a cell: the cell holds a rich value (`vm` on the cell, with `xl/metadata.xml` and the parts in `xl/richData`, its file in `xl/media`), with the description as its text. Pli reads the same parts back, so a picture Excel placed in a cell, or one Pli wrote, is the content of the cell, with its description; a kind of rich value that isn't a picture is left out with a warning. The parts are written the way Excel and XlsxWriter write them; they are checked for the mistakes that make Excel repair a file, and file 19 of the Excel check kit has them.

## Links and notes

A cell can lead somewhere (`link`) and can carry a note (`note`). Both are on the cell itself, so they are saved with the workbook, copied, cut, sorted and moved with it, and follow inserted rows.

```ts
session.setLink("Sheet1", "A1", { to: "https://pli.dev", tip: "The site" });   // keeps the cell's text and look
session.setLink("Sheet1", "B1", { to: "#Other!C3" }, { text: "The other sheet" });
session.link("Sheet1", "A1");          // { to: "https://pli.dev", tip: "The site" }
session.setNote("Sheet1", "D4", "Quote from the supplier");
session.notes("Sheet1");               // [{ address: "D4", text: "Quote from the supplier" }]
session.setNote("Sheet1", "D5", "Check the total now", {
  runs: [{ text: "Check the " }, { text: "total", bold: true, color: "#c00000" }, { text: " now" }],
  box: { width: 260, height: 110, show: true },        // a bigger box that stays showing
});
session.formatNote("Sheet1", "D5", 0, 5, { italic: true });   // characters 0 to 5 get a look
session.noteInfo("Sheet1", "D5");      // { text, runs, author?, box? }
session.showAllNotes("Sheet1");        // every note on the sheet stays showing (false hides them), one undo step
session.setNoteLook("Sheet1", "D5", { fill: "#ffcc00", transparency: 30, line: "#c00000", lineWeight: 2, dash: "dash", shadow: false });
session.setNoteLook("Sheet1", "D6", { picture: dataUri });     // a PNG, JPEG or GIF fills the box (Fill Effects > Picture)
session.formatNote("Sheet1", "D5", 6, 11, { link: "https://pli.dev" });   // a link inside the note's text
session.setCell("Sheet1", "A2", "www.pli.dev", { links: true });               // typing makes a link
```

- Where a link goes. A web address, `mailto:`, `tel:` or a file path, or, starting with `#`, a place in the workbook: `#Sheet2!B4`, `#B4` (this sheet), a range, or a defined name. `session.linkPlace(sheet, to)` says which sheet and range a place is. A link to a place on a sheet follows the sheet's new name when it is renamed (`#Other!B2` becomes `#'Second place'!B2`), which Excel itself doesn't do; it doesn't follow cells that move.
- Safe by construction. A link that would run a script (`javascript:`, `data:`, `vbscript:`, even spelled with spaces or tabs) is refused, in the model, in a saved workbook and in an XLSX file. The grid follows only web addresses, mail, phone and places in the workbook; a file path is shown but not opened.
- The text of a link is the cell's value. Typing new content into the cell takes the link off; the note stays (a note is kept when contents are cleared, as in Excel, and goes with Clear all).
- `HYPERLINK` formulas are links too: the card and Alt+Enter follow the address the formula works out to (`session.link` returns it, marked `formula`). It isn't a link to edit or remove, because it is the formula.
- A look. A link is drawn in the theme's hyperlink colour and underlined unless the cell has a colour or underline of its own (`linkedStyle(cell, palette)` gives the look; the XLSX file and the copied HTML use it). Office's hyperlink colour is blue (`#0563c1`) and its followed-hyperlink colour purple (`#954f72`); a workbook's `themeColors` can carry its own as its 11th and 12th colours (index 10 and 11, as `theme="10"` and `theme="11"` in a file), so changing the theme recolours every link, as it does in Excel. A link that has been followed (`CellLink.followed`, set by Ctrl or Cmd+click, Alt+Enter or the card's Open, or `session.followLink(sheet, address)`) takes the followed colour, as Excel's "Followed Hyperlink" cell style does. Following is not an edit: it isn't an undo step and is allowed on a protected sheet; a link that can't be followed (a place that isn't there, a file path) is not marked, and neither is the result of a `HYPERLINK` formula. Changing a link's address forgets that it was followed. In XLSX files a link cell uses Excel's "Hyperlink" cell style (underlined text in theme colour 10) or "Followed Hyperlink" (11), named in the stylesheet as Excel names them; reading, text in the file theme's hyperlink colour is a link that follows the theme and one in its followed colour a followed link (a colour of the cell's own stays as it is). LibreOffice keeps the theme colours and styles on a round trip.
- Copy and paste. A link goes out as an anchor in the HTML (`<a href>`), which Excel and Sheets paste as a link, and one comes in from their HTML (Google's redirect addresses are unwrapped). Notes travel with copied cells inside Pli.
- Notes are text up to 32,767 characters. The note shows beside the cell when the pointer rests on it or the cell is selected.
- A look for parts of a note. `Cell.note` stays the text, so anything that only knows plain notes keeps working; `noteRuns` beside it splits the text into runs that add up to it, each with `bold`, `italic`, `underline`, `strike`, `color` (`#rrggbb`), `size` (points) and `font`. Excel's default for a note (Tahoma 9, black) is the same as nothing. In the grid, the note editor (Insert > Note…, Shift+F2) has a toolbar for those and Ctrl or Cmd+B, I, U and 5 (strikethrough); Ctrl or Cmd+Enter saves. Pasting into it brings in plain text. `session.setNote(…, { runs })` sets runs (they have to match the text), `runs: null` makes the note plain, changing the text without runs drops them, and `session.formatNote(sheet, address, from, to, { bold: true })` styles a stretch (`null` takes a property off).
- An author. `noteAuthor` says who wrote the note. Pli never invents one: it comes from `<PliSheet author="Ana" />` or the session's `author` (`new SheetSession(wb, { author })`, or `session.author = …`), which you would fill from your signed-in user's name, and only new notes get it (editing a note keeps its author; `setNote(…, { author })` sets or, with `null`, takes it off). The card, the floating box and the editor show it in bold in front of the note ("Ana:"). In an XLSX file it is the comment's author, and, as Excel does, the first line of the text is the author in bold with a colon; Pli takes that line off when it reads a file back, so it isn't doubled. A note with no author is written with Excel's required author slot holding `Pli`, which reads back as no author.
- The box. `noteBox` is `{ width, height, dx, dy, show }` in pixels: the size (default 144 by 80), where the box's top left corner is from the cell's top right corner (default 15 across, 10 up; it moves with the cell), and `show: true` to keep the note on the sheet instead of only when the pointer rests on it. A note that shows is drawn as a box over the grid with a line to its cell, which you drag to move and resize with its handles (like a picture), with a **Hide note** button when the cell is selected and a double-click to edit. The card of a note that shows has Edit, **Hide note** and Delete. Insert > **Notes** has Show/hide note (the active cell), Show all notes, Hide all notes, Previous note, Next note and Delete note; the right-click menu has Show note / Hide note. `setNoteBox`, `showNote(sheet, address, show?)` and `showAllNotes(sheet, show?)` are the same on the session, each one undo step. Sizes are limited (at least 32 by 20 pixels, at most 2,000).
- A fill and a line for the box. The look of the box is on `noteBox` beside its size: `fill` (`#rrggbb`; Excel's note yellow `#ffffe1` when left out), `transparency` (0 to 100 percent of the fill or picture that lets the sheet show through; 100 is no fill), `picture` (a `data:` URI of a PNG, JPEG or GIF, up to 5 MB, drawn stretched over the box instead of the colour), `line` (`#rrggbb`, or `"none"` for no line; Excel's thin black line when left out), `lineWeight` (points, 0.25 to 100, 0.75 when left out), `dash` (`solid`, `dot`, `dash`, `dashDot`, `longDash`, `longDashDot`, `longDashDotDot`, `shortDash`, `shortDot`, `shortDashDot`, `shortDashDotDot`) and `shadow: false` to take Excel's shadow off. Whatever is Excel's usual is left out of the box. `session.setNoteLook(sheet, address, patch)` changes the look without touching the size or place (`null` for a property puts it back; one undo step), and `setNoteBox` replaces the whole box. In the grid, the note editor has a **Box: fill, picture, line and shadow** section (fill colour, transparency, a picture from a file with a thumbnail and Remove picture, line colour or No line, weight, dashes, shadow and **Usual look**); the editor itself takes the fill colour or picture so it shows how the note will look, and shown notes and the card of a selected cell are drawn with the fill (a layer behind the text, so a transparency lets the sheet show through), line, dashes and shadow. Moving or sizing a box keeps its look.
- Links in a note. A run can lead somewhere: `link` on a run in `noteRuns` (a web address, `mailto:`, `tel:`, or `#Sheet2!B4` for a place in the workbook; a script is refused as for cell links), set with `formatNote(…, { link })` or `setNote(…, { runs })`. In the editor, select the words and press **Link** (or Ctrl or Cmd+K), type the address (a bare `www.pli.dev` becomes `https://www.pli.dev`) and press Enter; with the caret inside a link the same button shows its address and has **Remove link**. A web address pasted over selected words becomes a link, and pasting formatted text keeps its bold, italic, underline, strikethrough, colour, size, font and links (black text and the note's own font and size count as no look, scripts and pictures are left out). A link is drawn blue and underlined and is followed by a click in a note that stays showing and in the card of the selected cell (it goes where a cell link goes: a new tab, mail, or a place in the workbook); the card that shows while the pointer rests on a cell vanishes when the pointer leaves, so it can't be clicked. Excel's notes can't hold links, so a link in a note is Pli's own: a file has the text of those words as plain text (with their bold and so on), and the address is not written. It comes back from Excel as text, not as a link, and it is kept in the model, in saved workbooks, copy and paste inside Pli, and undo.
- Typing with a look. With the caret on a point (nothing selected), Bold, Italic, Underline, Strikethrough, a font, a size or a colour is kept for what is typed next, as in Excel, and the buttons show it; moving the caret drops it.
- **In Excel files** the comment holds the runs (`<r><rPr>` with bold, italic, strike, underline, size, colour and font), the author is in the `<authors>` list and in front in bold, and the legacy drawing's shape holds the box: its anchor (cells and offsets, so the box moves and sizes with cells), width and height in the style, and `visibility:visible` with `<x:Visible/>` for a note that is kept showing. Reading takes the same back, from Excel's notes too (the author comes from the list, the position from the anchor, and the size from the style when there is no anchor); a colour from Excel's palette or theme becomes its `#rrggbb`. The look of the box is on the same shape: `fillcolor` (and `v:fill color2`), `v:fill opacity` (65536ths, `32768f` for half), `strokecolor` or `stroked="f"`, `strokeweight` (points), `v:stroke dashstyle`, and `<v:shadow on="f">` for no shadow; a picture is `<v:fill type="frame" o:relid="rId1" …>` with the image in the drawing's own relationships (`xl/drawings/_rels/vmlDrawingN.vml.rels`, the file in `xl/media`, a `Default` content type for its extension) as Excel's Fill Effects > Picture does. Reading takes the same back, from Excel's notes too: system colours (`infoBackground [80]`), colour names, `rgb()`, weights in points, pixels or EMU, `opacity` as a fraction, a percent or 65536ths, `filled="f"` as full transparency, and `<v:shadow on="f">` as no shadow; a picture that is missing or of a kind Pli doesn't keep (EMF, say) is left out with a warning and the note stays. Files 26 and 38 of the Excel check kit have the boxes and their looks.
- **In saved workbooks** `noteRuns`, `noteAuthor` and `noteBox` are checked as the rest of a cell is; an older workbook with only `note` reads as it did.

## How it works

Cells are positioned from the sheet's real widths and heights, so a sheet with a million rows costs nothing, and only the rows and columns in view are drawn. The sheet extends as you scroll or move toward its edge. A transparent scroll layer takes the mouse and keyboard, and one text field, invisible while you move around and the editor while you type, has the keyboard's focus, which is also what makes input methods, the clipboard events and screen reader announcements of the active cell work. Frozen rows and columns are drawn as separate panes.

## Build your own

`PliSheet` is made of public pieces: `Grid` (the grid, headers and editor, for a selection and an edit you hold yourself), `Axis` (column and row positions and the index at a pixel, which also suits a canvas or native drawing), `stepDecimals`, and the hooks. The selection and navigation logic (`moveSelection`, `jump`, `advance`, `selectionBounds`) and the clipboard and fill logic (`parseTsv`, `session.pasteText`, `session.autofill`) live in `@pli.dev/sheets`, with no UI, so another front end gets the same behaviour.

## Copy and paste

Copying puts three things on the clipboard: tab-separated text (what the cells show), an HTML table, and, for pasting back into Pli, a mark that the copy came from Pli.

- The HTML table has each cell's fill, text colour, bold, italic, underline, strikethrough, font and size, alignment and wrapping as inline styles, its borders as `border-*` styles, and merged ranges as `colspan` and `rowspan`. What conditional formats and a table's style do to a cell is included as the colours they give it. The widths of the columns and heights of the rows go with it (`<col width>` and `<tr height>`) when the sheet has sizes of its own there.
  - A data bar is a gradient in the cell's background as long as the bar (from the zero line, in the negative colour, with the axis drawn), an icon is the icon's own picture (the same SVG the grid draws) placed in the cell's background with room left for it, and the value is left out when the rule hides it. A diagonal border is a gradient line from corner to corner, and also Excel's `mso-diagonal-up` and `mso-diagonal-down`, which Excel reads. Excel and Google Sheets ignore backgrounds they don't know, so they paste the cell without the bar or icon; a browser, a mail program and Docs draw them. The table also carries `data-pli-cf`, the data bars and icon sets that covered the copied cells (kind, colours, ends or thresholds, hidden values) and where they began, so that pasting that HTML back into Pli makes the rules again, over the cells it lands on, with their formulas followed, replacing the rules that covered those cells, in the same undo step (only with Paste all or Formats). If the mark is lost on the way, a bar or icon is read from its picture: the icon set is the smallest one that holds the icons seen, with thresholds that give the same icons for the same numbers, and a bar's gradient gives the ends that make the same bars; negative bars, a zero line and colour scales are not rebuilt (a colour scale arrives as the colours it gave).
  - A whole [table](/sheets/tables/) (every cell of it, header included) is marked: its header cells are `<th>` (written with explicit weight and alignment so a reader that makes `<th>` bold and centred doesn't change them), and the `<table>` carries `data-pli-tables`, a JSON list of the table's name, place, columns, style, totals row, banding, first and last column, filter buttons and calculated columns. Excel and Sheets paste it as an ordinary range.
- Pasting from another program reads the table with `session.pasteHtml(sheet, at, html, options)`: Excel's classes and `<style>` block, Google Sheets' inline styles, and a plain page's table (`<th>` is bold and centred) all work. Exact numbers come from Excel's `x:num` and Sheets' `data-sheets-value`, a number format Sheets names is used when it produces the text shown, and anything else is read as if typed. A cell that shows `=A1` is text. The cells covered by the paste are replaced, formats and all, and merged ranges in the way are unmerged. Excel's default font (Calibri 11) and Sheets' (Arial 10) are left out, so pasted cells keep the grid's own.
  - Formulas. Excel writes `x:fmla` (A1 style, as the formula reads in its workbook; `x:fmla-range` or braces for an array formula) and Google Sheets `data-sheets-formula` (R1C1 style, relative to the cell, converted to A1 for the cell it lands in; `ARRAYFORMULA(…)` around all of it is dropped, as Pli spills by itself). The values the source showed are kept as the cached ones: Pli works the formula out itself. Excel doesn't say where the copied cells were, so Pli finds out, in this order: `source: "B2"` in the options says it outright (**Edit > Paste special > Formulas from Excel…** asks for the cell; leaving it empty is `source: "here"`, which takes the formulas as written, as if they were copied from where they land, and also brings the ones that point outside the copied cells); an array formula's `x:fmla-range` is an address in the Excel workbook, which fixes the position; otherwise, of the positions the formulas' references could mean, the one that makes every formula that points only inside the copied block give the value Excel showed is taken (never one that makes a formula read its own cell; the one that moves the references least if several do, and then `options.notes` says that more than one place fit). A formula is not brought, and its cell keeps the value, when it points outside the copied cells (Excel only), uses a function, name, table or sheet Pli doesn't have (Sheets' `IMPORTRANGE`, `QUERY`…), or no position fits the values; `options.notes` (and the grid's message line) says how many.
  - Sizes. The `<col>` widths, row `height`s and cell `width`/`height` of the source are read in pixels (Excel's points converted). Into empty space (no cells where the paste lands, no size set on those columns and rows) they are brought by default, as one undo step with the cells; **Paste special > Keep source column widths** (`widths: true`) brings them over any sizes, as Excel's does, and `widths: false` never does.
  - Tables. HTML marked by Pli's own copy creates the table again at the paste (header cells are its column names; the table's style takes over the colours the copy had baked into the cells): it keeps its name when no table or defined name has it, and gets the next free one (`Sales` gives `Sales2`) when not. `asRange: true` pastes plain cells. A table that would land on another table, or whose columns don't have distinct names, is pasted as cells.
- Pasting a copy made here (the clipboard still holds our own text) uses `session.copy` or `move`, which keep formulas, and carry merged cells, conditional formats and data validation with the cells: a rule that covered the copied cells covers where they land, with its formulas shifted as in Excel, and replaces what covered the cells pasted over. A cut takes the rule off the cells it left. Copying a whole table (every cell of it) creates a new table, as in Excel: its own name, the same style, banding, header and totals row, calculated columns, filter buttons, and no filter or sort (it shows all its rows); formulas in it that named the original name the copy (`Sales[Cost]` becomes `Sales2[Cost]`), and a copy that would land on another table is cells only. Cutting a whole table moves it (to another sheet too) with its name; part of a table is cells.
- Paste special (`options` of `copy` and `pasteHtml`; **Edit > Paste special** and the right-click menu): `content: "values"` pastes what the cells show and ignores formulas, looks, links and merged cells (the cells keep their own number format and style), `"formulas"` pastes formulas and values and keeps the cells' own looks, `"formats"` pastes looks, number formats and merged cells and keeps the cells' contents; `widths: true` brings the source's column widths and row heights; `asRange: true` pastes a table as plain cells. Ctrl+Shift+V (Cmd+Shift+V) is Values only. Each is one undo step.
- Transpose (`transpose: true`; **Edit > Paste special > Transpose**) turns the copy about its top left corner: the cell at row *i*, column *j* lands at row *j*, column *i*, for a copy made here, for another program's table and for plain text. What has a direction turns with it: the lines around a cell (a top border becomes a left one; the diagonals stay), merged cells (`A1:C1` becomes a column of three), conditional formats and data validation (their ranges, and their formulas, which read from the rule's first cell), and notes and links go along. Formulas follow Excel's rule: a relative reference keeps its distance from the cell with rows and columns exchanged (the cell to the left becomes the cell above, so a formula that read cells inside the copied block reads their turned copies); a reference with `$` on both the row and the column keeps pointing where it did; a mixed one (`$A1`) is turned as a whole (it becomes `A$1`); a reference pushed off the sheet is `#REF!`. As in Excel a table arrives as plain cells and column widths and row heights are not brought, and data bars and icon sets of a table pasted from another window are not rebuilt. A cut with Transpose moves the cells (the cut cells are cleared, but formulas elsewhere that read them are not rewritten). One undo step.
- The toolbar and menu **Paste** reads the HTML too where the browser allows it (`navigator.clipboard.read()`, which asks for permission); Ctrl+V always does.

- Excel's number formats. Excel's HTML says how each cell is shown with `mso-number-format` (in a class such as `.xl65` or on the cell): it is read into a Pli number format and kept with the exact number (`x:num`), so `2.50` comes as 2.5 shown `0.00`, a date as its serial shown `m/d/yyyy`, and `Short Date`, `Percent`, `Fixed`, `Long Time` and the other names as the formats they stand for. The Text format (`\@`) and `x:str` keep text that looks like a number, a formula or TRUE as text (`00123`); Google Sheets' text values are kept as text the same way. Copying out of Pli writes `mso-number-format` on every cell with a format, and marks text that Excel would turn into a number, date or formula as text, so Excel pastes the same formats and `00123` stays `00123`.
- Other things read from Excel's markup: the row of hidden empty cells Excel for Windows ends a table with is no row, spaces Excel marks as meant (`mso-spacerun`) are kept, line weights of 0.5, 1.5 and 2 points are thin, medium and thick, the Hyperlink look (blue, underlined) on a link is the link's own, rich-text runs written as `<font class=…>` give the cell their bold and colour, and the Latin-1 named entities (`&eacute;`) are decoded. From Google Sheets, the grid its stylesheet draws (`td {border: 1px solid #cccccc}`) is not pasted as borders.

### Checking the clipboard

The paste tests run on fixtures in `packages/sheets/test/fixtures/clipboard/` that follow what Excel (for Mac and Windows) and Google Sheets are documented to write: `excel-formats-mac.html` (every form of `mso-number-format`), `excel-layout-win.html` (merges, lines, links, text on several lines, booleans, errors, the hidden closing row), `google-sheets-mixed.html`, and tab-separated text from both (`excel-range.tsv`, `sheets-range.tsv`), with the user's name and paths left out. ### Checking the clipboard by hand

What the fixtures cannot say is what the real programs write today. To close that gap, try each of these once, in a browser with Pli.Sheets open, and compare with what is said (or save a capture as above, and the test does the comparing for items 1, 4 and 5):

1. **Excel, formulas.** In Excel, type `3`, `2.5` in B2 and C2 and `=B2*C2` in D2, with a total `=SUM(D2:D3)` in D4; copy B2:D4 and paste at F10 in Pli. Expected: the formulas read `F10*G10`, `SUM(H10:H11)` (shifted to where they land), the sums are formulas, no notice. Then copy only D2 (which points outside what was copied) and paste: expected a notice that one formula came as its value, and Edit > Paste special > Formulas from Excel… with `D2` as the cell brings the formula, moved by the distance. If the notice appears on a copy whose formulas all point inside what was copied, capture the clipboard (`swift scripts/capture-clipboard.swift excel-formulas`) and look at `x:fmla`.
2. **Excel, array formula.** Copy a dynamic or `{=…}` array formula's whole result range: expected its references move by the paste distance without being told (Excel writes `x:fmla-range`).
3. **Excel, data bars and icons.** Copy a range under a data bar and an icon set and paste in Pli. Expected: plain cells with Excel's colours, no rule (Excel's HTML has no bar or icon). If a capture shows anything about bars or icon sets in the HTML (look for `x14:`, `dataBar` or `iconSet`), that is a new fact: tell us.
4. **Excel, number formats.** Copy cells formatted `0.00`, `$#,##0.00`, a date and a percentage: expected the text and value right; the format is whatever the text reads as when typed.
5. **Google Sheets.** Copy a range with a number, a percentage, a date, a checkbox/boolean, a merged cell, a link, bold and a fill, plus formulas (`=B2*C2`, `=SUM(B2:B3)`, `=$B$2*2`, an `ARRAYFORMULA`, a `QUERY`). Expected: values, formats, merged cells, links and looks come across; formulas are formulas at their new place; `QUERY` stays its value with a notice. Check `data-sheets-value` for a boolean (`1`/`0` or `true`/`false`) and a date (the kind and serial number) in a capture: the fixture assumes both spellings of a boolean, numbers as serials and formats in `data-sheets-numberformat`.
6. **Transpose.** Copy a range with formulas, a merged cell and borders in Pli, then Edit > Paste special > Transpose in Pli and in Excel, and compare: formulas with relative references (Pli re-points them as Excel's documentation says; if Excel differs for `$A1` mixed references, or for references to cells outside the copied block, this is where to see it), borders (a top line becomes a left one), merged cells.
7. **Pli to Excel and Sheets.** Copy a range with a data bar and an icon set in Pli and paste into Excel and Sheets: expected the cell colours and text only. Paste the same into Pli in another window: expected the data bar and icons are rules again.

## Touch

The grid works with a finger as well as a mouse. When the first touch lands, the touch controls appear (they go away again when a mouse or pen is used), so a mouse user never sees them.

- Tap and scroll. A tap selects when the finger is lifted. A finger that moves more than a few pixels before it is lifted is a scroll: it selects nothing, and the grid scrolls as the browser scrolls it. Tapping a column or row heading selects it the same way.
- Long press (half a second without moving) opens the cell menu, selecting the cell first unless it is already inside the selection. A long press that the browser also reports as a context menu opens one menu, not two.
- Selection handles. A round handle outside the top left corner of the selection and one outside its bottom right corner stretch the selection from the opposite corner when dragged. A square handle under the selection fills: dragging it down or across does the same as the mouse's fill handle, with the same preview. The handles are not drawn on a read-only sheet, while typing, for whole columns or rows, or when several ranges are selected.
- Heading edges. Each column and row heading has a grip at its edge (wide enough for a fingertip); dragging it resizes that column or row, as the mouse does at the edge. The mouse's fill handle, selection edge and heading-edge hit areas are ignored for touch, since the handles and grips do that job.
- Move handle. A round handle with four arrows sits above the selection (or beside it when it is in the top rows, or at the left edge of the window): dragging it moves the selected cells by as far as the finger goes, with the same outline of where they will land as the mouse's drag of the selection's edge (red with the reason when the drop is refused), and the same rules: formulas that pointed at the cells follow them, merged cells go with them, one undo step. Lifting the finger puts them down, and a gesture the browser takes over (it cancels the touch) puts nothing down. It is offered where the other handles are, and not on a read-only sheet, while typing, for whole columns or rows, or when several ranges are selected. To copy instead of move, use Copy and Paste. The cells can't be dragged past the edge of the window yet (the grid does not scroll while the move handle is held).
- Tapping a cell while typing a formula puts its address in, as clicking does.

### Checking touch on a real device

The touch code is tested with synthetic pointer events in jsdom only (`packages/sheets-react/test/touch-ui.test.tsx` and `touch-move-ui.test.tsx`), which cannot say how a real finger, the browser's own scrolling and the on-screen keyboard behave. Checking it on a phone or tablet is for a person with the device. A short list for a pass (Safari on iPhone or iPad, Chrome on Android, with `pnpm playground` reachable from the device):

1. Tap a cell: it selects when the finger lifts. Drag a finger along the grid: it scrolls and selects nothing.
2. Touch and hold a cell for half a second: the cell menu opens once (not twice) on the cell.
3. Select a cell and drag its round corner handles: the selection stretches. Drag the square handle below it: the fill preview follows and fills when lifted.
4. Drag the round **move handle** above the selection: the outline follows the finger and the cells land there. Try it with a formula that points at them, and from the top row of the sheet (the handle should be beside it).
5. Drag the grip at the edge of a column heading and a row heading: they resize. Tap a heading: it selects.
6. Double tap a cell: the editor opens and the keyboard comes up. Type `=` and tap another cell: its address goes in.
7. Check that the page does not zoom or scroll sideways when a handle is dragged, and that a mouse or pen on a hybrid device takes the handles away again.

Write down the device, browser and anything that differs. No one has run this list on a device yet.

## Not there yet

- Badge cards: with several badges in a cell the keyboard opens only the first one's card (a click opens the one clicked), and a card can't be opened for a dropdown's badges, only for a kind your app defines.
- Checkboxes and badges have no Excel equivalent, so in an XLSX file they keep only their value; dropdowns become data validation lists (see [Files](/sheets/files/)).
- Groups, subtotals and sparklines: Excel has not been asked about any of it yet: the groups file (13) and the subtotal, date-axis and theme-colour file (30) have exact lists of what to look for, and file 41 (a converted table, merged labels, a pivot table below the list, a totals row with its functions, links and sparklines in the hyperlink colours) is new; LibreOffice agrees with what they hold. Not known without Excel: how it words its own refusal when the Subtotal command meets merged cells that rows would cut through (it is a greyed-out button over tables and pivot tables), and whether it draws the theme's two hyperlink colours as sparkline colours (they are in the file as `theme="10"` and `"11"`, which the format allows). `SPARKLINE` is Google's function; Excel has none, so such a cell shows `#NAME?` there (the chart is Pli's and Google's). Sparklines of the formula keep Google's `bar` and x axis only in a formula, not as Excel sparklines. Turning a table into a range (here and in Format > Table) leaves plain cells: the table style's colours are not kept as cell formatting, as Excel keeps them.
- Printing: not yet seen in Excel (files 29 and 40 of the check kit): the shape ids of the header and footer pictures (`LH`, `CHFIRST`, `RFEVEN`…, written with `o:spid`, a block of shape numbers of their own and the shape type, as Excel writes them, but only our own package check and LibreOffice have looked), whether Excel cuts text that runs on at a page break and the print area (Pli does, and prints none of it on the next page), whether it prints text running past the last used column (Pli does), what its draft quality leaves out (that depends on the printer), how it words the list of notes, and whether it cuts a note's box off at the print area as Pli does. Text running on is sized with Calibri's widths. Black and white turns charts and pictures grey rather than to Excel's patterns. Pictures in headers and footers are PNG, JPEG or GIF, with a crop and grayscale but no brightness or contrast, and the dialog adds them to the usual and first-page headers and footers (the even pages' are set with `setHeaderFooterPicture`). In the page break preview a drag does not scroll the sheet when it reaches the edge, a print range is made with Set print area (or by dragging an existing one) rather than by dragging out new cells, and it is for mouse and pen, not touch.
- PDF files: text is in the standard PDF fonts (stretched to Calibri's widths), so a script they don't have needs `fonts`; icon sets are drawn as lines and curves in the file, and charts of the common kinds too (column, bar, line, area, scatter, pie, doughnut: titles, legend, axes, stacking, colours, in two dimensions), with no host needed; the other kinds (3-D, radar, bubble, stock, surface, the newer statistical charts, and logarithmic or reversed axes) need `rasterize` (in `<PliSheet>`, a browser's canvas) and are a frame with a title without it; a picture's glow, soft edges and reflection are left out, its shadow is flat and a turned picture has no border or shadow; a JPEG with a crop, turn or corrections is printed as it is (there is no JPEG reader), and a GIF and a picture fetched from the web are left out; data bars are solid; a note's line to its cell isn't drawn; and the file has no bookmarks. `warnings` says what was left out. Pli can't send pages to a printer by itself: Print is the host's (`onPrint`), or Download PDF, or the browser's dialog when `browserPrint` is on.
- Protection, what is still open: Excel itself has not been asked about files 28 and 39 of the check kit. File 39 asks about the things Pli decided from Excel's documentation: that Excel agrees a row or column can be deleted only when all its cells are unlocked (and that a row you inserted can't be deleted), that it refuses to delete rows through a table on a protected sheet (Pli's guess), that `FORMULATEXT` of a hidden formula is `#N/A`, and how the `securityDescriptor` Pli writes (made-up SIDs, and Everyone) shows in Allow Edit Ranges, which on a Mac may not show accounts at all. Windows accounts need the application to say which SIDs a person has (Pli can't look names up), and only simple allow and deny entries are understood (the rest of a descriptor is kept as text). Roles of Pli's own are lost when Excel saves a file again. A row that hides formulas (or is locked) and crosses a column with a lock of its own takes the row's lock for its empty cells in an Excel file, since a row has one style. LibreOffice reads a cell that is locked on its own inside an unlocked column or row as unlocked. Threaded comments and track changes are not in the Review menu: they come with the comments and collaboration that every editor shares.
- Pictures, effects: Excel kept the glow, soft edges and shapes of files 27 and 37 of the check kit and the picture each artistic effect draws, but not the effect itself: its copy of the file had no `a14:imgProps`, so in Excel the picture was a plain picture. The layer was a PNG then; it is now an HD Photo, as Excel writes it, and whether Excel keeps the effect with that is not yet known (kit files 27, 37 and 45 ask it; file 45 writes the same Blur in eight forms of the layer so that, if Excel still drops it, the forms say which part it wants).
- Pictures, artistic effects: all twenty-two of Excel's effects are drawn, each Pli's own version rather than Excel's pixels. Format picture… has a slider for the level, with the effect's own range. The ranges of the ten added last (Marker, Chalk Sketch, Cement, Crisscross Etching, Light Screen, Pastels Smooth, Plastic Wrap, Texturizer, Watercolor Sponge, Paint Strokes) are from memory of Excel's panel, not checked against it (a value outside what Excel allows is clamped on reading); file 44 of the check kit lists them for someone with Excel to compare. A JPEG with arithmetic coding or 12 bits is not drawn here (written without the effect to an .xlsx file, and drawn through the browser's canvas on the sheet), and an animated GIF is its first picture.
- Pictures, shapes and keyboard crop: 36 of Office's shapes (not clouds, banners, other callouts, ribbons, waves, rings or frames: those are read as a rectangle, with a warning), with yellow handles on the rounded and snipped rectangles, the triangle, parallelogram, trapezoid, hexagon, octagon, cross, the block arrows, the stars and the three speech bubbles (the teardrop has none); a speech bubble's tail lies outside the picture's frame, so it shows only where it points into the picture; a click picks a picture by its rectangle, not its outline; a picture-filled shape (what LibreOffice writes) is not read as a picture. The shapes in .xlsx files are not yet seen in Excel (file 37 of the check kit). The keyboard crop cuts the picture's own sides even for a turned picture, and its screen reader text is checked as text (jsdom), not with a screen reader.
- Pictures, other effects: a reflection always lies directly under the picture (a reflection Excel wrote at another angle is read as one), the shadow is a box shadow so it doesn't follow soft edges, and glow, soft edges and reflection are for pictures only (not charts). 
- Notes: a link in a note's text is Pli's own and is written to an Excel file as plain text (Excel's notes can't hold links), so it does not survive a round trip through Excel; it is followed from a box that stays showing and from the card, including the card that shows while the pointer rests on a cell (the card waits a moment after the pointer leaves the cell, so the pointer can travel onto it). The text can't hold pictures or lists (Excel's notes can't either: a picture goes behind the text, as the box's fill, and a typed dash or number is just text). A fill, line or text colour that comes from an Excel theme is read as its `#rrggbb` and does not follow a theme change, and no fill is a transparency of 100 (there is no separate No fill). None of Excel 365's threaded comments (they are left out with a warning). The note boxes, their lines, fills, pictures and handles are checked with jsdom and LibreOffice (which reads a picture fill and writes it back without the picture), not yet in Excel itself (files 26 and 38 of the check kit await it: whether Excel keeps the picture fill, the opacity and the dashed lines as written). Links have no screen tip beyond the text you give, and open from Ctrl or Cmd+click on the cell, Alt+Enter or the card's Open, not from a plain click (a plain click only selects, as it has to for editing).
- Find and replace finds a look only by the properties above (not by a conditional format's colours), and looks in values, formulas or notes one at a time (as Excel does), not all at once.
- Filter views: a sorted view is drawn from a copy of the workbook with the view applied, so the cells you see are in the view's order but nothing in the sheet moves, and editing is off while it shows (Apply for everyone sorts the sheet, Close view brings it back). Copy, charts, find, print and the rest of the engine read the sheet's own rows, so they ignore the rows a view hides for you, and the filter buttons in the headings keep showing the sheet's own filters rather than the view's. Not built: filters by a conditional format's colour or a table style's, or with more than two comparisons. Changing cells under a filter doesn't reapply it; sorting through the menu does.
- Filter views in XLSX files: Excel for Mac opened kit file 32 with no repair message and kept all three views with their filters and their sort (it wrote each view's sort over the whole filter range, header row included, and Pli does the same); where Excel lists them (Windows, the web) has not been looked at. LibreOffice 26.8 reads the names and writes the views again from the state it has, so it is no check on their contents; older ones drop them. Not kept from a file: filters of a kind Pli doesn't have, sorts by colour, icon or custom list, sorts by several columns, and views for AutoFilters or tables that aren't in the file (each named in a warning). Google Sheets' filter views are not read or written.
- Borders, merged cells and conditional formatting are in: see [Borders, merged cells and conditional formats](/sheets/formatting/). Comments, people and live editing are in: see [Collaboration](/sheets/collaboration/).
- The grid is not exposed to screen readers as a table of cells: the active cell is announced as you move, but not its neighbours.
- Touch: the handles, the move handle, the grips, tap and long press are tested with synthetic touch events in jsdom only, not on a real phone or tablet: that is for a person with a device (a checklist is in [Checking touch on a real device](#checking-touch-on-a-real-device)). The move handle moves cells only (to copy, use Copy and Paste) and the grid does not scroll while it is dragged to the edge of the window. There is no pinch to zoom the grid, and double tap to edit relies on the browser's double click. Input methods, Safari, Firefox and mobile keyboards are not yet checked on real devices.
- Copy and paste, checked against sample HTML only (built from the formats Excel and Google Sheets document, one real Excel capture, and a Sheets fixture written to the markup Sheets is documented to use), never against the real programs: see the list of what to try by hand under [Copy and paste](#copy-and-paste). Excel's HTML carries no data bar or icon set (it flattens a rule to the colours it gave each cell) and Google Sheets has none besides colour scales, so those arrive as colours; the only bars and icons that come back as rules are Pli's own. Excel's number formats (`mso-number-format`) are read in all the forms Excel writes (`"0\.00"`, `Percent`, `"Short Date"`, `"\@"`, `"\0022$\0022\#\,\#\#0\.00"`…) and trusted; Sheets' format is used when it produces the text shown. Excel formulas whose position can't be told from the values (every formula points outside the copied cells, or no position gives the values shown) stay values unless the position is given (Formulas from Excel…); Sheets functions Pli doesn't have (`QUERY`, `IMPORTRANGE`…) stay as values. Dashed diagonal borders are drawn solid in the browser's picture (Excel gets the real style). A table copied to another Pli window comes back as a table, but its filter and sort do not. Pasting into a table's header row with a blank cell is refused. There is no "values and number formats" mix. Transpose does not rebuild data bars or icon sets of HTML from another window, and does not re-point formulas elsewhere that read cut cells.
